## Explication pas à pas

Dans une application, le même objet apparaît sous plusieurs formes. Un produit complet a un identifiant, un nom, un prix et un coût d’achat. Pour le créer, on n’a pas encore d’identifiant. Pour le modifier, on ne fournit que les champs qui changent. Pour l’afficher au public, on cache le coût d’achat. Recopier quatre interfaces presque identiques serait fragile : le jour où l’on ajoute une propriété, il faudrait penser à toutes les copies.

TypeScript fournit des types utilitaires qui dérivent un type d’un autre. Partial<Produit> rend toutes les propriétés optionnelles : c’est le type d’une modification partielle. Pick<Produit, "nom" | "prix"> ne garde que les propriétés citées. Omit<Produit, "coutAchat"> garde tout sauf les propriétés citées. Readonly<Produit> rend toutes les propriétés non modifiables. Required fait l’inverse de Partial.

Record<Cle, Valeur> décrit un objet utilisé comme dictionnaire : Record<string, number> associe des textes à des nombres. Avec une union de littéraux comme clé, Record<Statut, number> exige exactement une entrée par statut : en oublier une devient une erreur, ce qui en fait un excellent outil pour les compteurs et les tableaux de correspondance.

Ces types se combinent : type NouveauProduit = Omit<Produit, "id"> décrit les données envoyées pour créer un produit, type ModificationProduit = Partial<Omit<Produit, "id">> celles d’une mise à jour qui ne touche jamais à l’identifiant. Le modèle principal, Produit, reste l’unique source de vérité : si on lui ajoute une propriété, tous les types dérivés suivent automatiquement.

Quelques précautions. Pick et Omit vérifient les noms de propriétés : Pick<Produit, "nmo"> est refusé, ce qui protège des fautes de frappe. Readonly n’agit qu’en surface : les objets contenus restent modifiables. Et ces types n’existent qu’à la compilation : Omit ne retire pas la propriété d’un objet réel. Pour réellement ne pas envoyer le coût d’achat au public, il faut construire un nouvel objet sans cette propriété ; le type Omit vérifie seulement qu’on le fait.

Il existe d’autres utilitaires, comme ReturnType, qui donne le type du résultat d’une fonction, ou Awaited, qui donne le type résolu d’une promesse. On les découvre au fur et à mesure des besoins, dans la documentation officielle.

## Exemple guidé 1

```typescript
interface Produit {
  id: number;
  nom: string;
  prix: number;
  coutAchat: number;
}

type ProduitPublic = Omit<Produit, "coutAchat">;
type Modification = Partial<Omit<Produit, "id">>;

function publier(p: Produit): ProduitPublic {
  const { coutAchat, ...visible } = p;
  return visible;
}

function modifier(p: Produit, m: Modification): Produit {
  return { ...p, ...m };
}

const riz: Produit = { id: 1, nom: "riz", prix: 600, coutAchat: 450 };
console.log(publier(riz));
console.log(modifier(riz, { prix: 650 }).prix);
```

Affichage attendu :

    { id: 1, nom: 'riz', prix: 600 }
    650

Trace :

- Omit décrit le produit sans coût d’achat.
- La déstructuration retire vraiment la propriété de l’objet.
- Partial permet de ne modifier que le prix.

## Exemple guidé 2

```typescript
type Statut = "en attente" | "payée" | "livrée";

const compteur: Record<Statut, number> = { "en attente": 0, "payée": 0, "livrée": 0 };
for (const s of ["payée", "livrée", "payée"] as Statut[]) {
  compteur[s]++;
}
console.log(compteur);
```

Affichage attendu :

    { 'en attente': 0, 'payée': 2, 'livrée': 1 }

Trace :

- Record exige une entrée par statut.
- Oublier « livrée » serait une erreur.
- Le compteur se met à jour par clé.
