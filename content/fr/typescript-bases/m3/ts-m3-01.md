## Explication pas à pas

Beaucoup de données existent sous plusieurs formes qui n’ont pas les mêmes informations. Une forme géométrique est un cercle, avec un rayon, ou un rectangle, avec une largeur et une hauteur. Une commande est en attente, payée avec un montant, ou livrée avec une date. On pourrait tout mettre dans un seul objet avec des propriétés optionnelles, mais rien n’empêcherait alors un cercle sans rayon ou une commande livrée sans date.

L’union discriminée résout ce problème. Chaque forme est un type d’objet distinct, et toutes partagent une propriété commune dont la valeur est un texte littéral différent : type: "cercle" ou type: "rectangle". Cette propriété s’appelle le discriminant. L’union regroupe les formes : type Forme = Cercle | Rectangle.

Pour traiter une forme, on teste le discriminant, souvent avec un switch. Dans case "cercle", TypeScript sait que f est un cercle et autorise f.rayon ; dans case "rectangle", il autorise f.largeur. Chaque branche ne voit que les propriétés qui existent vraiment.

Le vrai bénéfice apparaît quand le modèle évolue. Si l’on ajoute un triangle à l’union, toutes les fonctions qui traitent les formes doivent être mises à jour. Pour que TypeScript les signale, on ajoute une branche default qui affecte la valeur à une variable de type never : const impossible: never = f. Le type never ne contient aucune valeur ; si tous les cas sont traités, f est bien de type never à cet endroit et la ligne compile. Si un cas a été oublié, f garde le type du cas oublié, et l’affectation devient une erreur qui désigne précisément la fonction à compléter. C’est ce qu’on appelle la vérification d’exhaustivité.

Ce modèle convient particulièrement aux états d’un processus, comme une commande ou une inscription, et aux actions d’une interface, comme dans les gestionnaires d’état de React. Il rend impossibles les combinaisons absurdes : une commande « en attente » ne peut pas avoir de date de livraison, puisque ce type ne la prévoit pas.

Un conseil de nommage : choisis un nom de discriminant cohérent dans tout le projet, comme type, kind ou statut, et des valeurs explicites en français ou en anglais, mais pas un mélange.

Cette technique est l’une des plus utiles de TypeScript : elle transforme des oublis, invisibles en JavaScript jusqu’au jour où un client rencontre le cas, en erreurs de compilation immédiates.

## Exemple guidé 1

```typescript
type Forme =
  | { type: "cercle"; rayon: number }
  | { type: "rectangle"; largeur: number; hauteur: number };

function aire(f: Forme): number {
  switch (f.type) {
    case "cercle":
      return Math.round(Math.PI * f.rayon * f.rayon);
    case "rectangle":
      return f.largeur * f.hauteur;
    default: {
      const impossible: never = f;
      return impossible;
    }
  }
}

console.log(aire({ type: "cercle", rayon: 2 }), aire({ type: "rectangle", largeur: 3, hauteur: 4 }));
```

Affichage attendu :

    13 12

Trace :

- Le discriminant type distingue les deux formes.
- Chaque case ne voit que les propriétés de sa forme.
- La branche default vérifie qu’aucun cas n’est oublié.

## Exemple guidé 2

```typescript
type Etat =
  | { statut: "en attente" }
  | { statut: "payée"; montant: number }
  | { statut: "livrée"; montant: number; date: string };

function decrire(e: Etat): string {
  switch (e.statut) {
    case "en attente":
      return "En attente de paiement";
    case "payée":
      return `Payée : ${e.montant} FCFA`;
    case "livrée":
      return `Livrée le ${e.date}`;
  }
}

console.log(decrire({ statut: "payée", montant: 4500 }));
console.log(decrire({ statut: "livrée", montant: 4500, date: "12 mai" }));
```

Affichage attendu :

    Payée : 4500 FCFA
    Livrée le 12 mai

Trace :

- Chaque état a ses propres informations.
- Une commande en attente n’a pas de montant.
- TypeScript sait que tous les cas renvoient une valeur.
