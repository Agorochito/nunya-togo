## Explication pas à pas

Certaines fonctions marchent avec n’importe quel type : renvoyer le premier élément d’un tableau, inverser une liste, envelopper une valeur. On pourrait leur donner le type any, mais on perdrait toute information : premier([1, 2, 3]) renverrait any, et une faute de frappe sur le résultat ne serait plus détectée.

Les génériques résolvent ce problème. On déclare un paramètre de type entre chevrons, souvent nommé T : function premier<T>(liste: T[]): T | undefined. Au moment de l’appel, TypeScript remplace T par le type réel : premier([1, 2, 3]) a le type number | undefined, premier(["riz"]) le type string | undefined. On écrit la fonction une seule fois, et chaque appel garde un type précis.

Tu as déjà utilisé des génériques sans le savoir : Array<number> est le type générique Array appliqué à number, et Promise<string> est une promesse de texte. Les méthodes map, filter et find sont génériques : notes.map(n => String(n)) renvoie un string[].

On peut avoir plusieurs paramètres de type : function paire<A, B>(a: A, b: B): [A, B]. On peut aussi écrire des types et des interfaces génériques : interface Reponse<T> { ok: boolean; donnees: T } décrit la réponse d’une API, quel que soit son contenu.

Parfois, la fonction a besoin que le type possède certaines propriétés. Pour trouver un élément par son identifiant, il faut que chaque élément ait un id. On contraint alors le paramètre : function trouver<T extends { id: number }>(liste: T[], id: number): T | undefined. Tout type qui possède un id numérique convient, produit, élève ou commande, et la fonction renvoie bien le type précis, pas seulement { id: number }.

Une règle simple aide à décider : si une fonction reçoit des valeurs et les renvoie, ou les range, sans dépendre de leur forme exacte, elle doit probablement être générique. Si le paramètre de type n’apparaît qu’une fois dans la signature, il est inutile : un type ordinaire suffit.

Les génériques sont la base des bibliothèques réutilisables : collections, outils de requêtes, gestionnaires d’état. Ils permettent d’écrire du code à la fois souple et précis, ce que any ne permet jamais.

## Exemple guidé 1

```typescript
function premier<T>(liste: T[]): T | undefined {
  return liste[0];
}

function paire<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}

const n = premier([10, 20]);
const nom = premier(["Afi", "Yao"]);
console.log(n, nom?.toUpperCase(), paire("riz", 600));
```

Affichage attendu :

    10 AFI [ 'riz', 600 ]

Trace :

- T devient number pour le premier appel, string pour le second.
- nom garde le type string : toUpperCase est autorisé.
- paire garde le type de chaque position.

## Exemple guidé 2

```typescript
function trouver<T extends { id: number }>(liste: T[], id: number): T | undefined {
  return liste.find(e => e.id === id);
}

const eleves = [{ id: 1, nom: "Ama", classe: "1re D" }];
const e = trouver(eleves, 1);
console.log(e?.classe);
```

Affichage attendu :

    1re D

Trace :

- T doit avoir un id numérique.
- Le résultat garde le type complet de l’élève.
- On peut donc lire classe.
