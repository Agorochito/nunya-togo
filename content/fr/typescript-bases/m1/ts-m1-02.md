## Explication pas à pas

TypeScript reprend les types primitifs de JavaScript : string pour le texte, number pour tous les nombres, entiers ou décimaux, boolean pour true et false, ainsi que null et undefined. On les écrit en minuscules : string, et non String, qui désigne autre chose.

Un tableau se type par le type de ses éléments suivi de crochets : number[] pour une liste de notes, string[] pour une liste de noms. On peut aussi écrire Array<number>, qui est équivalent. TypeScript refuse alors d’ajouter un texte dans un number[], et sait que notes[0] est un number. Attention : en mode strict par défaut, notes[10] reste typé number même si l’élément n’existe pas ; la vérification des indices ne remplace pas la prudence.

Un tuple est un tableau de longueur fixe dont chaque position a son propre type : [string, number] décrit une paire comme ["riz", 600]. Il convient aux petites structures dont l’ordre a un sens, comme le résultat d’une fonction qui renvoie deux valeurs. Pour plus de deux ou trois éléments, un objet aux propriétés nommées est plus lisible.

Les types littéraux restreignent une valeur à quelques possibilités : let direction: "nord" | "sud" n’accepte que ces deux textes. On les retrouvera avec les unions au module 2.

Deux types spéciaux méritent attention. any désactive toute vérification : une valeur any peut être utilisée n’importe comment, et les erreurs réapparaissent à l’exécution. C’est une porte de sortie pour du vieux code, à éviter dans du code neuf. unknown est son équivalent sûr : une valeur unknown peut contenir n’importe quoi, mais TypeScript interdit de l’utiliser tant qu’on n’a pas vérifié son type. C’est le bon type pour une donnée dont on ignore la forme, comme le résultat de JSON.parse.

Enfin, les annotations de tableau évitent une erreur subtile. Un tableau vide déclaré sans type, const panier = [], peut recevoir n’importe quoi selon les réglages. Annoter const panier: string[] = [] dit clairement ce qu’il contiendra.

Les vérifications de l’atelier contrôlent parfois qu’une valeur incorrecte est refusée. Si ton tableau est typé any[], la vérification échoue : tes types sont trop larges. Un type précis protège davantage qu’un type permissif.

## Exemple guidé 1

```typescript
const notes: number[] = [12, 15, 9];
notes.push(17);
const article: [string, number] = ["riz", 600];
const [nom, prix] = article;
console.log(notes.length, nom, prix * 2);
```

Affichage attendu :

    4 riz 1200

Trace :

- notes n’accepte que des nombres.
- Le tuple a un texte puis un nombre.
- La déstructuration garde les types de chaque position.

## Exemple guidé 2

```typescript
const brut: unknown = JSON.parse("[1, 2, 3]");
if (Array.isArray(brut)) {
  console.log("tableau de", brut.length, "éléments");
}
let libre: any = "texte";
console.log(libre.toFixed === undefined);
```

Affichage attendu :

    tableau de 3 éléments
    true

Trace :

- unknown oblige à vérifier avant d’utiliser.
- Après Array.isArray, brut est connu comme tableau.
- any laisse tout passer : libre.toFixed n’est même pas signalé.
