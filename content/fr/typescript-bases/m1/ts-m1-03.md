## Explication pas à pas

Une fonction typée annonce son contrat. function remise(prix: number, pourcentage: number): number dit qu’elle attend deux nombres et renvoie un nombre. TypeScript vérifie les appels, avec le bon nombre d’arguments et les bons types, et vérifie aussi le corps : si un chemin de la fonction oublie de renvoyer un nombre, l’erreur est signalée.

Une fonction qui ne renvoie rien, comme une fonction qui affiche, a pour type de retour void. Annoter le retour n’est pas obligatoire, car TypeScript le devine, mais c’est une bonne habitude pour les fonctions importantes : une modification accidentelle du corps sera signalée au lieu de changer silencieusement le contrat.

Un paramètre optionnel s’écrit avec un point d’interrogation : function saluer(nom: string, titre?: string). À l’intérieur, titre a le type string | undefined : TypeScript oblige à prévoir son absence. Une valeur par défaut, function saluer(nom: string, titre = "élève"), rend le paramètre optionnel et lui donne un type déduit de la valeur. Les paramètres optionnels se placent toujours après les obligatoires.

Les fonctions sont des valeurs : on peut les passer en argument. Leur type s’écrit comme une flèche : (n: number) => number désigne une fonction qui reçoit un nombre et renvoie un nombre. C’est le type du paramètre de map, de filter ou d’un rappel. Quand on passe une fonction fléchée directement, TypeScript devine le type de ses paramètres à partir du contexte : dans notes.map(n => n * 2), n est un number sans annotation.

Le type des fonctions async est Promise suivi du type du résultat entre chevrons : async function charger(): Promise<string>. On retrouvera cette notation générique au module 3.

Une erreur fréquente concerne le nombre d’arguments. En JavaScript, appeler une fonction avec un argument de moins donne undefined en silence ; en TypeScript, c’est une erreur, sauf si le paramètre est optionnel. De même, un argument de trop est refusé.

Typer précisément les fonctions est l’investissement le plus rentable de TypeScript : les fonctions sont les points de contact entre les parties d’un programme, et c’est là que les malentendus coûtent le plus cher.

## Exemple guidé 1

```typescript
function saluer(nom: string, titre?: string): string {
  return titre ? `Bonjour ${titre} ${nom}` : `Bonjour ${nom}`;
}

function appliquer(valeurs: number[], f: (n: number) => number): number[] {
  return valeurs.map(f);
}

console.log(saluer("Afi"), "|", saluer("Mensah", "Mme"));
console.log(appliquer([1, 2, 3], n => n * 10));
```

Affichage attendu :

    Bonjour Afi | Bonjour Mme Mensah
    [ 10, 20, 30 ]

Trace :

- titre est optionnel : son absence est prévue.
- f est une fonction de nombre vers nombre.
- Dans la flèche, n est deviné comme number.

## Exemple guidé 2

```typescript
function afficherTicket(lignes: string[]): void {
  for (const l of lignes) console.log("-", l);
}

function remise(prix: number, pourcentage = 10): number {
  return prix - Math.round(prix * pourcentage / 100);
}

afficherTicket(["riz", "sel"]);
console.log(remise(5000), remise(5000, 20));
```

Affichage attendu :

    - riz
    - sel
    4500 4000

Trace :

- void : la fonction affiche mais ne renvoie rien.
- pourcentage vaut 10 par défaut.
- On peut le préciser quand on veut.
