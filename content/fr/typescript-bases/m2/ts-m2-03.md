## Explication pas à pas

L’erreur la plus fréquente en JavaScript est « Cannot read properties of undefined » : on lit une propriété sur une valeur absente. Son inventeur a qualifié la référence nulle d’« erreur à un milliard de dollars ». En mode strict, TypeScript la rend presque impossible : null et undefined ne sont plus acceptés partout, ils doivent figurer explicitement dans le type.

Une fonction qui peut ne rien trouver le dit dans sa signature : function chercher(id: number): Produit | undefined. Le tableau find de JavaScript fait déjà cela : produits.find(…) a le type Produit | undefined. Tant qu’on n’a pas vérifié, TypeScript interdit d’écrire resultat.nom. Après if (resultat === undefined) return …, ou if (resultat), la suite du code sait que resultat existe.

Deux opérateurs raccourcissent ces vérifications. Le chaînage optionnel ?. lit une propriété seulement si la valeur existe, et donne undefined sinon : client?.adresse?.ville. L’opérateur de coalescence ?? fournit une valeur de remplacement quand la gauche est null ou undefined : quantite ?? 1.

Attention à la différence entre ?? et ||. L’opérateur || remplace toutes les valeurs « fausses », y compris 0 et la chaîne vide. Avec stock || 10, un stock réellement nul de 0 devient 10, une erreur grave. Avec stock ?? 10, seul un stock absent devient 10. Pour des nombres, ?? est presque toujours le bon choix.

L’opérateur d’assertion non nulle, le point d’exclamation après une valeur, valeur!, dit à TypeScript « je sais que ce n’est pas null ». Il fait taire l’erreur sans rien vérifier : si tu te trompes, le programme plante à l’exécution. Garde-le pour les rares cas où tu sais vraiment, et préfère une vérification explicite.

Les propriétés optionnelles vues dans la leçon sur les interfaces suivent la même logique : telephone?: string a le type string | undefined.

Le mode strict regroupe d’autres vérifications, comme l’interdiction des paramètres sans type. Dans un projet existant écrit sans strict, l’activer révèle souvent des dizaines d’erreurs : chacune est un plantage possible qui attendait son heure. C’est pourquoi les équipes l’activent dès le début des nouveaux projets.

Pense à l’absence comme à un cas normal, à traiter, et non comme à une exception : un client sans téléphone, un produit introuvable, une note non encore saisie font partie de la réalité.

## Exemple guidé 1

```typescript
interface Produit {
  nom: string;
  stock?: number;
}

const produits: Produit[] = [{ nom: "riz", stock: 0 }, { nom: "sel" }];
const trouve = produits.find(p => p.nom === "huile");
console.log(trouve?.nom ?? "introuvable");
console.log(produits[0].stock ?? 10, produits[0].stock || 10, produits[1].stock ?? 10);
```

Affichage attendu :

    introuvable
    0 10 10

Trace :

- find peut renvoyer undefined : ?. évite le plantage.
- ?? garde le stock 0, || le remplace à tort par 10.
- Le stock absent du sel devient 10.

## Exemple guidé 2

```typescript
function initiales(nom: string | null): string {
  if (nom === null) {
    return "?";
  }
  return nom.split(" ").map(m => m[0]).join("");
}

console.log(initiales("Ama Mensah"), initiales(null));
```

Affichage attendu :

    AM ?

Trace :

- nom peut être null : le type le dit.
- La vérification rétrécit le type.
- Après le if, nom est un string.
