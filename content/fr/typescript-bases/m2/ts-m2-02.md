## Explication pas à pas

Beaucoup de valeurs peuvent prendre plusieurs formes. Un identifiant peut être un nombre ou un texte ; une saisie peut être un nombre ou null ; un paiement peut être en espèces ou par mobile money. TypeScript décrit ces situations avec une union, écrite avec une barre verticale : string | number signifie « un texte ou un nombre ».

Une union de types littéraux est particulièrement utile : type Statut = "en attente" | "payée" | "livrée" n’accepte que ces trois textes exacts. Une faute de frappe comme "livré" devient une erreur de compilation, et l’éditeur propose les valeurs possibles. C’est souvent plus sûr qu’une simple chaîne.

Sur une union, TypeScript n’autorise que ce qui est valable pour tous les membres. Avec id: string | number, on ne peut pas appeler id.toUpperCase(), car un nombre n’a pas cette méthode. Il faut d’abord rétrécir le type, c’est-à-dire vérifier quel membre on a. Après if (typeof id === "string"), TypeScript sait qu’à l’intérieur du bloc id est un string, et dans le else, un number. Ce suivi du raisonnement s’appelle l’analyse de flux.

Plusieurs vérifications rétrécissent : typeof pour les types primitifs, Array.isArray pour les tableaux, l’égalité avec une valeur littérale, === null, et l’opérateur in pour savoir si un objet possède une propriété : if ("numero" in paiement). Un return anticipé rétrécit aussi : après if (typeof x === "string") return …, la suite du code sait que x n’est plus un texte.

Les unions remplacent avantageusement les valeurs « magiques ». Au lieu de renvoyer -1 pour signaler une absence, une fonction peut renvoyer number | null : l’appelant est obligé de traiter le cas null, alors qu’un -1 oublié se propage dans les calculs.

Ne confonds pas une union de tableaux et un tableau d’union : string[] | number[] est soit une liste de textes, soit une liste de nombres ; (string | number)[] est une liste qui mélange les deux.

Les unions et le rétrécissement sont au cœur de TypeScript : ils permettent de modéliser fidèlement les cas réels, puis de garantir que chaque cas est traité. La leçon suivante les applique au problème le plus fréquent : les valeurs null et undefined.

## Exemple guidé 1

```typescript
type Statut = "en attente" | "payée" | "livrée";

function libelle(id: string | number, statut: Statut): string {
  const code = typeof id === "string" ? id.toUpperCase() : "N°" + id.toFixed(0);
  return code + " : " + statut;
}

console.log(libelle("cmd-12", "payée"));
console.log(libelle(48, "livrée"));
```

Affichage attendu :

    CMD-12 : payée
    N°48 : livrée

Trace :

- id est un texte ou un nombre.
- typeof rétrécit : chaque branche connaît le type exact.
- statut n’accepte que trois textes précis.

## Exemple guidé 2

```typescript
type Paiement = { especes: number } | { numero: string; montant: number };

function decrire(p: Paiement): string {
  if ("numero" in p) {
    return "Mobile money " + p.numero + " : " + p.montant;
  }
  return "Espèces : " + p.especes;
}

console.log(decrire({ especes: 2000 }));
console.log(decrire({ numero: "90 12 34 56", montant: 3500 }));
```

Affichage attendu :

    Espèces : 2000
    Mobile money 90 12 34 56 : 3500

Trace :

- Un paiement a l’une de deux formes.
- in vérifie la présence de numero.
- Après le if, TypeScript sait qu’il reste les espèces.
