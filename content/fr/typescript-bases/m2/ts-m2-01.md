## Explication pas à pas

Les programmes manipulent surtout des objets : un élève, un produit, une commande. TypeScript permet de décrire leur forme une fois pour toutes. Une interface s’écrit interface Produit { nom: string; prix: number; } : tout objet de type Produit doit avoir un nom textuel et un prix numérique. On l’utilise ensuite comme n’importe quel type : function prixTTC(p: Produit): number.

Un alias de type fait presque la même chose : type Produit = { nom: string; prix: number }. Les deux sont interchangeables dans la plupart des cas. On préfère souvent interface pour les objets, car elle peut être étendue avec extends, et type pour les unions et les combinaisons, vues dans la leçon suivante.

TypeScript compare les formes, pas les noms : un objet qui a les bonnes propriétés convient, même s’il n’a jamais été déclaré comme Produit. C’est le typage structurel. Il y a une exception utile : quand on écrit directement un objet littéral à la place d’un Produit, une propriété inconnue est signalée. Écrire { nom: "riz", prx: 600 } révèle ainsi une faute de frappe.

Une propriété optionnelle se marque d’un point d’interrogation : telephone?: string. Elle peut manquer ; à l’intérieur du code, elle a le type string | undefined et doit être vérifiée avant usage. Une propriété readonly ne peut plus être modifiée après la création de l’objet : readonly id: number protège un identifiant contre une modification accidentelle.

Les interfaces se composent. interface Eleve extends Personne { classe: string } ajoute des propriétés à une interface existante. Une propriété peut avoir pour type une autre interface, ou un tableau d’interfaces : lignes: LigneCommande[]. On construit ainsi le modèle de données d’une application, souvent le premier fichier qu’on écrit dans un projet TypeScript.

Ce modèle sert de documentation vivante. Quand une collègue lit function inscrire(e: Eleve), elle sait exactement ce qu’il faut fournir, et son éditeur lui propose les propriétés au fur et à mesure qu’elle tape. Si le modèle change, par exemple si classe devient obligatoire, toutes les fonctions qui créent des élèves incomplets sont signalées d’un coup.

Rappelle-toi enfin que ces vérifications portent sur le code, pas sur les données reçues à l’exécution : un JSON venu d’un serveur ne devient pas un Produit valide parce qu’on l’annote ainsi. Le module 4 montrera comment le vérifier vraiment.

## Exemple guidé 1

```typescript
interface Produit {
  readonly id: number;
  nom: string;
  prix: number;
  promo?: number;
}

function prixFinal(p: Produit): number {
  return p.promo !== undefined ? p.promo : p.prix;
}

const riz: Produit = { id: 1, nom: "riz", prix: 600 };
const huile: Produit = { id: 2, nom: "huile", prix: 1500, promo: 1300 };
console.log(prixFinal(riz), prixFinal(huile));
```

Affichage attendu :

    600 1300

Trace :

- L’interface décrit la forme d’un produit.
- promo est optionnelle : elle est vérifiée avant usage.
- id est en lecture seule.

## Exemple guidé 2

```typescript
interface Personne {
  nom: string;
}

interface Eleve extends Personne {
  classe: string;
  notes: number[];
}

const afi: Eleve = { nom: "Afi", classe: "1re D", notes: [14, 16] };
console.log(afi.nom, afi.classe, afi.notes.length);
```

Affichage attendu :

    Afi 1re D 2

Trace :

- Eleve étend Personne et hérite de nom.
- notes est un tableau de nombres.
- L’objet doit avoir les trois propriétés.

Écris l’interface d’un élève de ta classe : propriétés obligatoires, optionnelles et en lecture seule.
