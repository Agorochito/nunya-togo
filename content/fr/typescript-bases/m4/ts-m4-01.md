## Explication pas à pas

Les classes de JavaScript reçoivent en TypeScript des types et des protections. On déclare chaque propriété avec son type : nom: string. Une propriété doit être initialisée, soit directement, soit dans le constructeur ; en mode strict, une propriété oubliée est une erreur.

Le modificateur private interdit l’accès à une propriété depuis l’extérieur de la classe. Un compte bancaire garde son solde en private : le code extérieur ne peut pas écrire compte.solde = 1000000, il doit passer par les méthodes deposer et retirer, qui vérifient les montants. C’est l’encapsulation : l’état interne n’est modifié que par des chemins contrôlés. Le modificateur protected autorise en plus les classes filles. JavaScript propose aussi ses propres champs privés, écrits avec un dièse, #solde, qui sont protégés même à l’exécution.

readonly rend une propriété non modifiable après la construction : un titulaire ou un identifiant ne change pas. Un raccourci permet de déclarer et d’affecter une propriété directement dans les paramètres du constructeur : constructor(private readonly id: number).

Une interface peut décrire le contrat que plusieurs classes doivent respecter. interface Forme { aire(): number } exige une méthode aire renvoyant un nombre. class Carre implements Forme oblige Carre à fournir cette méthode avec la bonne signature ; si elle manque ou renvoie un texte, la compilation échoue. Le code qui utilise des formes peut alors recevoir un Forme[] et appeler aire sur chacune, sans savoir s’il s’agit de carrés ou de cercles.

Les méthodes peuvent lever des erreurs pour refuser une opération invalide : retirer plus que le solde, déposer un montant négatif. Le type ne peut pas tout vérifier : qu’un montant soit positif dépend de la valeur, connue seulement à l’exécution. Types et vérifications à l’exécution se complètent.

Faut-il toujours des classes ? Non. En TypeScript, beaucoup de code s’écrit avec des fonctions et des interfaces, comme dans les modules précédents. Les classes sont utiles quand un objet a un état interne à protéger et des opérations qui le font évoluer : un compte, un panier, une connexion.

Comme toujours, ces protections disparaissent après la compilation pour private et readonly : elles empêchent les erreurs de programmation, pas un code malveillant. Pour un vrai secret, il faut une vraie barrière, comme un serveur.

## Exemple guidé 1

```typescript
class Compte {
  private solde = 0;
  readonly titulaire: string;

  constructor(titulaire: string) {
    this.titulaire = titulaire;
  }

  deposer(montant: number): void {
    if (montant <= 0) throw new Error("montant invalide");
    this.solde += montant;
  }

  retirer(montant: number): void {
    if (montant <= 0 || montant > this.solde) throw new Error("retrait impossible");
    this.solde -= montant;
  }

  consulter(): number {
    return this.solde;
  }
}

const compte = new Compte("Ama");
compte.deposer(5000);
compte.retirer(1500);
console.log(compte.titulaire, compte.consulter());
try {
  compte.retirer(10000);
} catch (e) {
  console.log((e as Error).message);
}
```

Affichage attendu :

    Ama 3500
    retrait impossible

Trace :

- Le solde est privé : on le modifie seulement par les méthodes.
- Le titulaire est en lecture seule.
- Un retrait trop grand est refusé par la méthode.

## Exemple guidé 2

```typescript
interface Forme {
  aire(): number;
}

class Carre implements Forme {
  constructor(private readonly cote: number) {}
  aire(): number {
    return this.cote * this.cote;
  }
}

class Disque implements Forme {
  constructor(private readonly rayon: number) {}
  aire(): number {
    return Math.round(Math.PI * this.rayon ** 2);
  }
}

const formes: Forme[] = [new Carre(3), new Disque(1)];
console.log(formes.map(f => f.aire()));
```

Affichage attendu :

    [ 9, 3 ]

Trace :

- Les deux classes respectent le contrat Forme.
- Le constructeur déclare et affecte la propriété.
- Le tableau de Forme mélange les deux sortes.

## Vérifier et expliquer

Choisis un objet de la vie courante qui a un état à protéger, comme un porte-monnaie, et écris les méthodes qui peuvent le modifier.
