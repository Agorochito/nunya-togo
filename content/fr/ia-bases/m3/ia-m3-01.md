## Explication pas à pas

Un modèle apprend de ses exemples, avec leurs qualités et leurs défauts. Si les exemples représentent mal une partie de la population, le modèle se trompera davantage pour elle. On parle de biais : une erreur systématique qui touche certains groupes plus que d’autres.

Les biais ont des origines variées. Le déséquilibre : un modèle de reconnaissance vocale entraîné surtout sur des voix d’adultes parlant le français de Paris comprend moins bien les accents d’Afrique de l’Ouest ou les voix d’enfants. Les étiquettes : si des décisions passées étaient injustes, par exemple des prêts refusés plus souvent à certaines personnes, le modèle apprend à reproduire cette injustice. Les variables : un modèle qui utilise le quartier d’habitation peut défavoriser indirectement les habitants de certains quartiers, même si l’origine des personnes n’est jamais donnée.

Ces biais ont été observés dans des systèmes réels : des logiciels de reconnaissance faciale beaucoup moins précis pour les peaux foncées, des outils de tri de candidatures qui défavorisaient les femmes parce qu’ils avaient appris des embauches passées. Les conséquences sont concrètes : un service refusé, une personne suspectée à tort.

La première défense est de mesurer. On commence par la répartition des données : quelle part des exemples vient de chaque groupe ? Puis, après l’apprentissage, on calcule l’exactitude, les faux positifs et les faux négatifs pour chaque groupe séparément. Une exactitude globale de 90 % peut cacher 95 % pour un groupe majoritaire et 60 % pour un groupe minoritaire. On calcule l’écart entre le meilleur et le moins bon groupe, et on le compare à une tolérance fixée à l’avance.

Ces mesures demandent de connaître le groupe de chaque exemple, ce qui pose une question délicate : certaines informations, comme l’origine ou la religion, sont sensibles et protégées par la loi. On les collecte seulement si c’est nécessaire, avec des garanties, et souvent seulement pour l’audit.

Quand un biais est détecté, plusieurs remèdes existent : collecter davantage d’exemples pour le groupe sous-représenté, corriger les étiquettes, retirer une variable problématique, ou renoncer à automatiser la décision. La recommandation de l’UNESCO sur l’éthique de l’IA insiste sur ce dernier point : pour les décisions importantes, un humain doit pouvoir comprendre, contester et corriger le résultat. Un modèle n’est jamais neutre par nature ; il reflète les choix faits pour le construire.

## Exemple guidé 1

```python
from collections import Counter

groupes = ["ville"] * 8 + ["village"] * 2
print(Counter(groupes))
print(Counter(groupes)["village"] / len(groupes))
```

Affichage attendu :

    Counter({'ville': 8, 'village': 2})
    0.2

Trace :

- Huit exemples sur dix viennent de la ville.
- Le village ne représente que 20 % des données.
- Le modèle risque d’être moins bon pour lui.

## Exemple guidé 2

```python
def exactitude_par_groupe(predictions, verites, groupes):
    resultat = {}
    for g in sorted(set(groupes)):
        paires = [(p, v) for p, v, x in zip(predictions, verites, groupes) if x == g]
        resultat[g] = round(sum(1 for p, v in paires if p == v) / len(paires), 2)
    return resultat

print(exactitude_par_groupe(['oui', 'oui', 'non', 'oui', 'non', 'non', 'oui', 'non', 'oui', 'oui'], ['oui', 'oui', 'non', 'oui', 'non', 'oui', 'non', 'oui', 'oui', 'non'], ['ville', 'ville', 'ville', 'ville', 'ville', 'village', 'village', 'village', 'ville', 'village']))
```

Affichage attendu :

    {'village': 0.0, 'ville': 1.0}

Trace :

- Globalement, 6 prédictions sur 10 sont justes.
- Pour la ville, toutes sont justes.
- Pour le village, aucune : la moyenne cachait tout.
