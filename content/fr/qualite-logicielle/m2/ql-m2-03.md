## Explication pas à pas

Certains bugs sont si fréquents qu’ils ont un nom. Les connaître fait gagner des heures, car leurs symptômes sont déroutants : le programme ne plante pas, il se comporte de façon étrange.

Premier piège : la valeur par défaut modifiable. def ajouter(article, panier=[]) semble créer un panier vide à chaque appel. En réalité, la liste par défaut est créée une seule fois, quand Python lit la définition de la fonction, puis partagée entre tous les appels. Le deuxième client retrouve les articles du premier dans son panier ! La règle : ne jamais utiliser une liste, un dictionnaire ou un ensemble comme valeur par défaut. On écrit panier=None, puis, dans la fonction, if panier is None: panier = [].

Deuxième piège : comparer des nombres à virgule avec ==. Les ordinateurs stockent les flottants en binaire, et beaucoup de décimales, comme 0,1, n’ont pas de représentation exacte. 0.1 + 0.2 vaut 0.30000000000000004, et 0.1 + 0.2 == 0.3 est faux. Pour comparer des flottants, on utilise math.isclose(a, b), qui tolère une infime différence. Pour l’argent, on préfère travailler en entiers : en francs CFA, qui n’ont pas de centimes, ou en centimes pour d’autres monnaies.

Troisième piège : modifier une liste pendant qu’on la parcourt. Supprimer des éléments avec remove dans une boucle for sur la même liste décale les indices, et la boucle saute des éléments. Le résultat dépend des données : certaines listes donnent le bon résultat, d’autres non, ce qui rend le bug difficile à voir. La solution est de construire une nouvelle liste avec les éléments à garder, souvent par compréhension, ou de parcourir une copie.

Quatrième piège : la division entière par erreur. En Python 3, / donne toujours un flottant et // une division entière. Utiliser // pour une moyenne perd les décimales en silence.

Cinquième piège : confondre is et ==. is teste s’il s’agit du même objet en mémoire, == teste l’égalité des valeurs. Pour comparer des nombres ou des textes, on utilise toujours == ; is est réservé à None : if valeur is None.

Ces pièges ont un point commun : un test bien choisi les révèle. Un test qui appelle deux fois la fonction démasque le premier ; un test avec 0,1 et 0,2, le deuxième ; un test avec deux éléments consécutifs à supprimer, le troisième.

## Exemple guidé 1

```python
def ajouter(article, panier=[]):
    panier.append(article)
    return panier

print(ajouter("riz"))
print(ajouter("savon"))

def ajouter_sur(article, panier=None):
    if panier is None:
        panier = []
    panier.append(article)
    return panier

print(ajouter_sur("riz"))
print(ajouter_sur("savon"))
```

Affichage attendu :

    ['riz']
    ['riz', 'savon']
    ['riz']
    ['savon']

Trace :

- La liste par défaut est partagée entre les appels.
- Le deuxième client hérite du riz.
- Avec None par défaut, chaque appel crée son propre panier.

## Exemple guidé 2

```python
import math

print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3, math.isclose(0.1 + 0.2, 0.3))
notes = [8, 9, 12, 7]
for n in notes:
    if n < 10:
        notes.remove(n)
print(notes)
```

Affichage attendu :

    0.30000000000000004
    False True
    [9, 12]

Trace :

- 0,1 + 0,2 n’est pas exactement 0,3 en binaire.
- isclose tolère la petite différence.
- Supprimer pendant le parcours saute le 9 : il reste dans la liste.

## Vérifier et expliquer

Écris un test qui révèle chacun des trois premiers pièges, et vérifie qu’il échoue sur la version fautive.
