## Explication pas à pas

Jusqu’ici, tu vérifiais tes programmes en les lançant et en regardant l’affichage. Cette méthode a deux défauts : il faut tout revérifier à chaque modification, et l’œil laisse passer des erreurs. Les développeurs professionnels écrivent des tests automatiques, des programmes qui vérifient d’autres programmes. Une équipe peut alors modifier son code sans crainte : si quelque chose casse, un test le signale aussitôt.

L’outil le plus simple est l’instruction assert. assert condition ne fait rien si la condition est vraie, et lève une AssertionError si elle est fausse. On peut ajouter un message : assert prix_ttc(1000) == 1180, "TVA de 18 % attendue". Le message s’affiche quand le test échoue et aide à comprendre pourquoi.

Par convention, on regroupe les vérifications d’une fonction dans une fonction de test dont le nom commence par test_ : test_prix_ttc. Elle appelle la fonction testée avec des valeurs choisies et compare chaque résultat à la valeur attendue, calculée à la main. Si toutes les assertions passent, la fonction de test se termine sans rien dire. L’outil pytest, très utilisé en entreprise, trouve automatiquement toutes les fonctions test_ d’un projet, les exécute et affiche un résumé ; il s’installe sur un ordinateur, mais le principe est exactement celui que tu pratiques ici.

Une question essentielle se pose : un test qui passe prouve-t-il quelque chose ? Un test vide passe toujours, sans rien vérifier. Un bon test doit échouer quand le code est faux. Pour le vérifier, les exercices de ce cours utilisent une méthode professionnelle appelée test par mutation : une fonction d’évaluation, fournie, remplace la fonction testée par plusieurs versions volontairement défectueuses, les mutants, puis relance ton test. Ton test doit passer avec la vraie fonction et échouer avec chaque mutant. Un mutant qui survit révèle un cas que ton test ne vérifie pas.

Choisis les valeurs de test avec soin. Une seule valeur ne suffit presque jamais : un calcul faux peut donner le bon résultat par hasard. Teste un cas ordinaire, un cas limite, comme zéro ou une liste vide, et un cas où une erreur de calcul ferait une vraie différence, par exemple un prix qui ne tombe pas rond.

Enfin, un test vérifie le comportement, pas l’écriture du code : il ne dit pas comment calculer, il dit ce qu’on doit obtenir.

## Exemple guidé 1

```python
def prix_ttc(prix_ht):
    return round(prix_ht * 1.18)


def test_prix_ttc():
    assert prix_ttc(1000) == 1180
    assert prix_ttc(0) == 0
    assert prix_ttc(250) == 295


test_prix_ttc()
print("Tous les tests passent")
```

Affichage attendu :

    Tous les tests passent

Trace :

- Chaque assert compare un résultat à la valeur calculée à la main.
- Les trois conditions sont vraies : rien ne se passe.
- Le message final s’affiche.

## Exemple guidé 2

```python
def prix_ttc(prix_ht):
    return prix_ht + 18


try:
    assert prix_ttc(1000) == 1180, "TVA de 18 % attendue"
except AssertionError as erreur:
    print("Test échoué :", erreur)
```

Affichage attendu :

    Test échoué : TVA de 18 % attendue

Trace :

- La fonction ajoute 18 au lieu de 18 %.
- L’assertion est fausse : AssertionError.
- Le message explique ce qui était attendu.
