## Explication pas à pas

Dans les leçons précédentes, chaque cas de test occupait une ligne assert. Quand les cas se multiplient, ce code se répète : seules les valeurs changent. On sépare alors les données des vérifications. Les cas sont rangés dans une liste de tuples, chacun contenant l’entrée et le résultat attendu ; une boucle parcourt la liste et vérifie chaque cas. On parle de tests pilotés par les données, ou tests en tableau.

Ajouter un cas devient trivial : une ligne de plus dans le tableau. Le tableau se lit comme une spécification : on voit d’un coup d’œil toutes les situations prévues, comme dans un tableau de tarifs. Un collègue peut le relire et dire « il manque le cas du montant nul » sans lire la moindre ligne de logique.

Il faut toutefois soigner le message d’échec. Dans une boucle, un simple assert ne dit pas quel cas a échoué. On ajoute donc un message qui contient l’entrée, le résultat obtenu et le résultat attendu : assert remise(m) == attendu, (m, remise(m), attendu). En cas d’échec, l’AssertionError affiche ce tuple, et l’on sait immédiatement quelle ligne du tableau corriger ou quel code examiner.

Les cas d’un tableau suivent la méthode de la leçon précédente : un représentant de chaque classe, et des valeurs de chaque côté de chaque frontière. Pour une remise de 5 % à partir de 10 000 FCFA et de 10 % à partir de 50 000, on teste 9 999, 10 000, 49 999 et 50 000, et un montant nul.

pytest propose une écriture équivalente, plus confortable : un décorateur, pytest.mark.parametrize, prend le tableau et génère un test séparé par ligne, chacun avec son propre rapport. unittest, intégré à Python, propose subTest dans le même esprit. La logique reste celle de la boucle que tu écris ici.

Un piège guette les tableaux : calculer l’attendu avec la fonction testée elle-même, par exemple attendu = remise(m). Le test devient alors toujours vrai et ne vérifie rien. Les valeurs attendues s’écrivent en dur, calculées à la main ou tirées d’une source indépendante, comme un tarif officiel ou un exemple donné par la cliente.

Enfin, un tableau de cas sert de documentation vivante : il montre des exemples concrets d’utilisation de la fonction, et il reste à jour, puisque les tests échouent s’il ne l’est plus.

## Exemple guidé 1

```python
def remise(montant):
    if montant >= 50000:
        return montant * 10 // 100
    if montant >= 10000:
        return montant * 5 // 100
    return 0

CAS = [
    (9999, 0),
    (10000, 500),
    (49999, 2499),
    (50000, 5000),
]


def test_remise():
    for montant, attendu in CAS:
        assert remise(montant) == attendu, (montant, remise(montant), attendu)


test_remise()
print(len(CAS), "cas vérifiés")
```

Affichage attendu :

    4 cas vérifiés

Trace :

- Chaque tuple contient le montant et la remise attendue.
- La boucle vérifie chaque ligne.
- Les quatre cas encadrent les deux frontières.

## Exemple guidé 2

```python
def remise(montant):
    return montant * 5 // 100


CAS = [(9999, 0), (10000, 500)]
try:
    for montant, attendu in CAS:
        assert remise(montant) == attendu, (montant, remise(montant), attendu)
except AssertionError as e:
    print("Échec :", e)
```

Affichage attendu :

    Échec : (9999, 499, 0)

Trace :

- La version fautive donne une remise sous 10 000 FCFA.
- Le message indique le montant, l’obtenu et l’attendu.
- On sait immédiatement quel cas corriger.

## Vérifier et expliquer

Ajoute à un tableau de cas une ligne volontairement fausse et lis le message d’échec produit.
