## Explication pas à pas

Imagine un programme de change où le taux euro-franc CFA, 655,957, apparaît à six endroits. Ce taux est fixe, mais une erreur de frappe dans une seule copie, 656 au lieu de 655.957, suffit à donner des résultats incohérents entre deux écrans. Ce nombre écrit en dur, sans nom, s’appelle un nombre magique : le lecteur ne sait pas d’où il vient, et le développeur ne sait pas où il est utilisé.

La solution est une constante : TAUX_EURO = 655.957, en majuscules selon la convention Python, définie une seule fois en haut du fichier et utilisée partout. Le code devient lisible, montant * TAUX_EURO dit ce qu’il fait, et le taux ne peut plus diverger. Le même raisonnement vaut pour les seuils : 20000 pour la livraison gratuite, 10 pour la moyenne, 18 pour la TVA. Ces nombres méritent tous un nom.

Ce principe a un nom en anglais, DRY : Don’t Repeat Yourself, ne te répète pas. Il s’applique aussi aux blocs de code. Quand tu copies-colles trois lignes pour les adapter légèrement, tu crées deux endroits à maintenir. Le jour où l’on découvre un bug dans ces lignes, on le corrige souvent dans une seule copie : l’autre garde le bug. C’est l’une des sources de bugs les plus fréquentes dans les vrais projets. On rassemble donc le bloc dans une fonction, et les différences deviennent des paramètres.

Parfois, la répétition est dans les données plutôt que dans la logique. Trois fonctions frais_lome, frais_kara, frais_sokode, qui ne diffèrent que par un montant, se remplacent par un dictionnaire TARIFS et une seule fonction frais(zone) qui le consulte. Ajouter une ville devient l’ajout d’une ligne, sans écrire de code. Cette table de données se lit comme une grille tarifaire et se vérifie d’un coup d’œil.

Attention à ne pas exagérer. Deux bouts de code qui se ressemblent par hasard, mais qui représentent des règles différentes, peuvent rester séparés : si la règle de l’un change, l’autre ne devrait pas suivre. La question à se poser est : « si cette connaissance change, ces deux endroits doivent-ils changer ensemble ? » Si oui, rassemble-les.

Enfin, le remaniement se fait toujours sous la protection des tests : on vérifie que le comportement reste le même après avoir rassemblé le code.

## Exemple guidé 1

```python
TAUX_EURO = 655.957


def en_fcfa(euros):
    return round(euros * TAUX_EURO)


def en_euros(fcfa):
    return round(fcfa / TAUX_EURO, 2)

print(en_fcfa(10), en_euros(6560))
```

Affichage attendu :

    6560 10.0

Trace :

- Le taux est défini une seule fois.
- Les deux fonctions utilisent la même valeur.
- Changer le taux ne demanderait qu’une modification.

## Exemple guidé 2

```python
TARIFS = {"Lomé": 500, "Kara": 2500, "Sokodé": 2000}


def frais(zone):
    if zone not in TARIFS:
        raise ValueError("zone inconnue : " + zone)
    return TARIFS[zone]


print(frais("Kara"))
try:
    frais("Paris")
except ValueError as e:
    print(e)
```

Affichage attendu :

    2500
    zone inconnue : Paris

Trace :

- La grille tarifaire est une donnée, pas du code.
- Une seule fonction remplace trois copies.
- Une zone absente est refusée clairement.
