## Explication pas à pas

Le défaut le plus fréquent d’une page sur téléphone est le défilement horizontal : un élément plus large que l’écran oblige le visiteur à faire glisser la page sur le côté, et toute la mise en page semble cassée. Trois causes reviennent presque toujours : une image trop large, une largeur fixe et un mot très long.

Une image de 800 pixels de large garde sa taille naturelle, même sur un écran de 360 pixels. La règle img { max-width: 100%; height: auto } règle le problème pour toute la page. max-width: 100% interdit à l’image de dépasser la largeur de son conteneur ; height: auto garde ses proportions quand elle rétrécit. Les attributs width et height écrits dans le HTML restent utiles : ils indiquent les proportions au navigateur, qui réserve la bonne place avant le chargement.

Les largeurs fixes posent le même problème. width: 900px sur main force une largeur de 900 pixels, quel que soit l’écran. On la remplace par max-width: 900px, qui fixe seulement un maximum : sur un grand écran, le bloc mesure 900 pixels ; sur un téléphone, il prend la largeur disponible. Comme vu au module précédent, on préfère max-width presque partout.

Un mot ou une adresse très longue sans espace, comme une adresse web, ne peut pas aller à la ligne et dépasse. La propriété overflow-wrap: anywhere autorise le navigateur à couper un mot trop long n’importe où quand c’est nécessaire. Elle est utile sur les paragraphes qui contiennent des adresses, des noms de fichiers ou des identifiants.

Les tableaux et les blocs de code peuvent aussi déborder. Pour eux, on préfère laisser défiler le bloc lui-même plutôt que toute la page : overflow-x: auto sur un conteneur crée une barre de défilement locale, et le reste de la page reste stable.

Pour détecter ces problèmes, réduis la fenêtre de ton navigateur à 360 pixels ou utilise le mode téléphone des outils de développement, puis cherche une barre de défilement horizontale. Dans les exercices, l’aperçu vérifie le style calculé à 360 pixels. Sur une vraie page, ce contrôle prend une minute et évite la première impression d’un site cassé.

Ces règles simples sont si utiles que beaucoup de développeurs les placent au début de chaque feuille de style, avant tout le reste.

## Exemple guidé 1

```html
<!doctype html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Ama Mensah — page personnelle</title>
  <style>
    img {
      max-width: 100%;
      height: auto;
    }
    p {
      overflow-wrap: anywhere;
    }
  </style>
</head>
<body>
  <main>
    <img src="portrait-ama.jpg" alt="Portrait d’Ama Mensah souriante" width="800" height="600">
    <p>Mon adresse de projet : https://exemple.github.io/un-tres-long-nom-de-depot-sans-espace</p>
  </main>
</body>
</html>

```

Résultat attendu : L’image et la longue adresse restent dans l’écran de 360 pixels.

Trace :

- max-width: 100% limite l’image à son conteneur.
- height: auto garde les proportions.
- overflow-wrap: anywhere coupe l’adresse si besoin.

## Exemple guidé 2

```html
<!doctype html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Ama Mensah — page personnelle</title>
  <style>
    main {
      max-width: 900px;
      margin: 0 auto;
    }
  </style>
</head>
<body>
  <main>
    <p>Contenu principal.</p>
  </main>
</body>
</html>

```

Résultat attendu : Un bloc de 900 pixels au plus, qui rétrécit sur téléphone.

Trace :

- max-width fixe un maximum.
- Sur 360 pixels, main prend la largeur disponible.
- Aucun défilement horizontal.

## Vérifier et expliquer

Réduis la fenêtre de ton navigateur à 360 pixels sur une page de ton choix et cherche ce qui dépasse.
