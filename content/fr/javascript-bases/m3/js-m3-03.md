## Explication pas à pas

Une boucle permet de traiter plusieurs données successives. Pour garder un résultat entre les passages, on déclare une variable avant la boucle. Un accumulateur conserve une valeur partielle, par exemple la somme déjà obtenue. Un compteur conserve le nombre de fois où un événement s’est produit. Les deux évoluent par affectation, mais ils ne répondent pas à la même question.

Pour une somme, l’accumulateur commence à zéro. À chaque passage, total = total + valeur ajoute la nouvelle donnée au résultat précédent. Avec les valeurs deux, cinq et un, les états du total sont zéro avant le parcours, puis deux, sept et huit. Afficher seulement huit ne montre pas cette construction ; une trace sur papier permet de vérifier que chaque valeur a été utilisée une fois.

Le lieu de l’initialisation est décisif. Si let total = 0 se trouve dans le bloc répété, un nouveau total est préparé à chaque passage et le passé est perdu. Si une variable doit servir après la boucle, elle doit aussi être accessible à cet endroit. Déclarer le résultat avant la répétition rend visibles sa préparation, ses mises à jour et son utilisation finale.

Un compteur sous condition ne change pas à chaque passage. Pour compter les valeurs strictement positives, on part de positifs = 0 et on ajoute un seulement lorsque valeur > 0 est vrai. Le nombre zéro n’est pas positif dans ce contrat strict. Un accumulateur de somme peut, lui, ajouter toutes les valeurs, y compris les négatives. Traiter trois données ne signifie pas trouver trois données positives.

Une saisie peut annoncer combien de valeurs seront lues. Dans nos exercices, ce nombre est un entier validé entre zéro et cinq. Le programme lit ensuite exactement ce nombre de réponses. La boucle for convient à ce contrat : le compteur de parcours i vérifie le nombre de lectures, tandis que total et positifs conservent deux résultats différents. Ne réutilise pas le même nom pour ces rôles.

Avec zéro donnée, la somme reste zéro et le compteur reste zéro. Cette situation n’autorise pas une moyenne calculée par division par zéro. Si une moyenne est demandée, il faut prévoir explicitement le cas sans valeur ; ici nous travaillons d’abord les totaux et les comptages. Les nombres utilisés sont fictifs et ne décrivent aucun compte financier ni groupe réel.

Teste une série contenant zéro, une valeur négative et plusieurs valeurs différentes. Si tous les essais utilisent le même nombre répété, une erreur peut rester invisible. Après exécution, compare le total, le compteur et le nombre de lectures avec ta trace. Une sortie correcte sur une seule série n’est pas encore une preuve générale, mais plusieurs cas choisis mettent à l’épreuve les étapes qui construisent le résultat.

## Exemple guidé 1

```javascript
let total=0;
for(let i=1;i<=3;i=i+1){total=total+i;}
console.log(total);
```

Saisies scriptées : [].

Résultat attendu :

```text
6
```

Trace :

- total commence à 0.
- Avec i=1, total devient 1.
- Avec i=2, total devient 3 ; avec i=3, il devient 6.
- La boucle se termine puis affiche le total conservé.

## Exemple guidé 2

```javascript
const nombre=Number(input("Combien ?"));
let total=0;
let positifs=0;
for(let i=0;i<nombre;i=i+1){
  const valeur=Number(input("Valeur ?"));
  total=total+valeur;
  if(valeur>0){positifs=positifs+1;}
}
console.log(total);
console.log(positifs);
```

Saisies scriptées : ["3", "-2", "0", "5"].

Résultat attendu :

```text
3
1
```

Trace :

- nombre vaut 3 et les deux résultats commencent à 0.
- La valeur -2 donne total=-2 et aucun positif.
- La valeur 0 laisse total=-2 et positifs=0.
- La valeur 5 donne total=3 et positifs=1 ; ces deux résultats sont affichés.
