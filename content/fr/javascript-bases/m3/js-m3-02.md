## Explication pas à pas

La boucle for convient lorsque le parcours est organisé par un compteur. La boucle while met d’abord en évidence une condition de poursuite : tant que le test reste vrai, le bloc recommence. Le moteur vérifie ce test avant chaque passage. Si le test est déjà faux, le bloc ne s’exécute pas. La valeur utilisée pour ce test doit donc être préparée avant la boucle.

Dans un décompte, on peut initialiser restant à trois, puis répéter tant que restant > 0. Le bloc affiche restant et le diminue d’une unité. La trace donne trois, deux et un ; après la dernière diminution, restant vaut zéro. Le prochain test est faux. Contrairement à une variable déclarée seulement dans l’en-tête d’un for, ce nom déclaré avant le while reste disponible après la boucle.

La fin doit être construite. Si le bloc ne change jamais ce qui rend le test vrai, le programme peut répéter indéfiniment. Ne prends pas le temps maximal du moteur pour une règle de calcul. Avant d’exécuter, identifie la valeur qui évolue, le sens de son évolution et l’état qui arrête la répétition. Pour le décompte, diminuer restant nous rapproche de zéro ; l’augmenter ferait le contraire.

Une attente de réponse demande une autre précaution. L’auxiliaire input de Nunya lit une liste finie de saisies scriptées. Il ne fait apparaître aucune fenêtre et ne demande pas au réseau d’attendre une réponse. Si le code lit plus de réponses que le test n’en fournit, le moteur signale une erreur de saisies. Une limite d’essais permet d’exprimer un contrat fini et compréhensible.

Pour accepter un entier de un à cinq, on peut conserver un booléen valide et un nombre essais. Au départ, valide est faux et essais vaut zéro. Tant que la réponse n’est pas valide et que trois essais ne sont pas atteints, le programme lit un texte, le nettoie, vérifie présence et conversion, puis augmente essais. Cette augmentation est nécessaire même après une réponse incorrecte.

Le contrat doit préciser ce qui est compté : ici chaque lecture consomme un essai, y compris la réponse finalement acceptée. À la sortie, on distingue la réussite de l’épuisement des essais. Teste une réponse correcte immédiatement, une correction après un refus, puis trois refus. Prévois seulement les saisies réellement nécessaires dans chaque cas ; cette trace vérifie à la fois le résultat et l’ordre des demandes, sans boucle sans fin.

## Exemple guidé 1

```javascript
let restant=3;
while(restant>0){
  console.log(restant);
  restant=restant-1;
}
console.log("Terminé");
```

Saisies scriptées : [].

Résultat attendu :

```text
3
2
1
Terminé
```

Trace :

- restant commence à 3 ; le test est vrai.
- Chaque passage affiche puis retire un : 3, 2 et 1 sont affichés.
- Après le troisième passage restant vaut 0 ; le test devient faux.
- L’instruction après la boucle affiche Terminé.

## Exemple guidé 2

```javascript
let essais=0;
let mot="";
while(mot!=="fin"&&essais<3){
  mot=input("Écris fin pour arrêter").trim().toLowerCase();
  essais=essais+1;
}
console.log(essais);
```

Saisies scriptées : ["suite", " FIN "].

Résultat attendu :

```text
2
```

Trace :

- essais vaut 0 et mot est vide : le premier test est vrai.
- La première saisie suite ne termine pas l’attente ; essais devient 1.
- La seconde saisie devient fin après nettoyage ; essais devient 2.
- Le test mot!==fin est alors faux, donc le programme affiche 2.
