## Explication pas à pas

Nous savons choisir une action ; nous voulons maintenant répéter une action. Une boucle est une structure qui exécute plusieurs fois un bloc. Chaque passage s’appelle une itération. Avec for, trois éléments placés dans les parenthèses décrivent le parcours : une initialisation, un test de poursuite et une mise à jour. Les points-virgules séparent ces trois éléments ; ils ne sont pas des messages à afficher.

Dans for (let i = 0; i < 3; i = i + 1), i commence à zéro. Avant chaque passage, le moteur vérifie i < 3. Si le test est vrai, il exécute le bloc entre accolades, puis ajoute un à i. Il recommence le test avec la nouvelle valeur. Les valeurs utilisées dans le bloc sont donc zéro, un et deux. Quand i vaut trois, le test est faux et la boucle se termine.

La mise à jour ne se produit pas avant le premier passage. Ce détail explique pourquoi une trace doit comporter la valeur au moment du test, l’action du bloc puis la nouvelle valeur. Prépare un petit tableau sur papier. Pour trois passages, écris chaque état au lieu de résumer « cela répète trois fois ». Cette trace permet de comprendre le résultat et de repérer une borne incorrecte.

Une autre convention peut commencer à un et aller jusqu’à trois inclus. Elle utilise i = 1 et i <= 3. Elle effectue aussi trois passages mais affiche les numéros un, deux et trois. Le nombre de passages et les valeurs affichées sont deux informations distinctes. Choisis la convention adaptée au contrat : positions à partir de zéro ou numéros à partir de un. N’ajoute pas simplement un symbole égal sans vérifier ce qu’il change.

Un nombre de passages peut venir d’une saisie déjà validée. Pour les exercices de cette leçon, le contrat garantit un entier entre zéro et dix. Quand ce nombre vaut zéro, une boucle commençant à zéro avec i < nombre ne doit pas exécuter son bloc. Ce cas vide est utile : répéter zéro fois est un résultat normal, pas une panne. Un texte annoncé après la boucle peut tout de même être affiché.

Le nom i déclaré dans l’en-tête sert au suivi local de la boucle. Si un résultat doit rester disponible après, déclare une autre variable avant la boucle ; nous travaillerons ces compteurs dans la suite. Ici, privilégie une répétition courte et finie. Ne lance pas un programme dont tu ne peux pas expliquer comment le test deviendra faux. Le bouton d’arrêt est une protection, pas un remplacement du raisonnement sur la fin.

## Exemple guidé 1

```javascript
for(let i=0;i<3;i=i+1){
  console.log(i);
}
```

Saisies scriptées : [].

Résultat attendu :

```text
0
1
2
```

Trace :

- L’initialisation fixe i à 0.
- Le test est vrai pour 0 : la console affiche 0 ; la mise à jour donne 1.
- Le test est vrai pour 1 puis 2 : ces valeurs sont affichées.
- Après la mise à jour à 3, le test est faux et aucun autre affichage n’a lieu.

## Exemple guidé 2

```javascript
const nombre=Number(input("Nombre de fiches ?"));
for(let numero=1;numero<=nombre;numero=numero+1){
  console.log("Fiche "+String(numero));
}
console.log("Fin");
```

Saisies scriptées : ["2"].

Résultat attendu :

```text
Fiche 1
Fiche 2
Fin
```

Trace :

- La saisie 2 devient le nombre 2.
- numero commence à 1 ; 1<=2 est vrai et la première fiche est annoncée.
- Après mise à jour, 2<=2 est vrai : la deuxième fiche est annoncée.
- À 3 le test devient faux ; le programme affiche ensuite Fin.
