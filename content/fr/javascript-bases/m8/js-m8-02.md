## Explication pas à pas

Nous avons maintenant des fiches questions et une règle de correction. Il faut produire un bilan pour une série de réponses. Le tableau questions définit le total prévu. Le tableau reponses peut être plus court si la personne s’est arrêtée. Nous choisissons une règle explicite : une réponse absente est comptée comme non réussie, sans fabriquer une saisie vide ou une preuve que la personne a essayé cette question. Le bilan peut garder séparément le nombre de réponses présentes.

Pour chaque position du tableau de questions, retrouve la réponse correspondante. Avant d’appeler trim, vérifie qu’il s’agit bien d’une chaîne. Une position absente donne undefined ; tenter immédiatement une méthode de texte provoquerait une erreur. Dans notre projet, cette absence produit le booléen false. Ce choix ne s’applique pas à toutes les applications : il appartient au contrat de ce questionnaire, avec des réponses courtes uniquement.

La fonction corrigerSerie(questions,reponses) renvoie un nouveau tableau de booléens. Il possède exactement autant d’éléments que questions. À chaque tour, elle utilise la même normalisation de texte, puis ajoute le résultat. Les données d’entrée ne changent pas. On peut lire cette trace pour expliquer quelles questions sont à revoir, puis utiliser une deuxième fonction pour compter les valeurs true sans refaire les comparaisons.

Un score est un nombre de réussites sur un total. Un pourcentage éventuel se calcule seulement si le total est supérieur à zéro. Nous adoptons Math.round pour arrondir au nombre entier le plus proche ; ce service mathématique ne transforme pas le score en certificat. Pour une série vide, le contrat renvoie un bilan avec score zéro, total zéro et pourcentage null : aucune question n’a été évaluée. Afficher 100 pour cent dans ce cas fabriquerait une réussite sans activité.

Prépare des exemples qui distinguent réussite, échec et absence : deux réponses exactes sur trois, aucune réponse présente, puis zéro question. Si tu ne testes que trois réussites sur trois, une fonction qui renvoie systématiquement 100 peut sembler correcte. Vérifie aussi l’ordre des booléens : il doit suivre les questions, car les identifiants de fiches serviront plus tard à indiquer les notions à revoir.

Le bilan doit rester sobre et utile à l’apprentissage. Il décrit ce qui a été essayé selon notre règle, pas la valeur d’une personne ou son aptitude à un métier. Dans un vrai site, la sauvegarde et les évaluations peuvent avoir d’autres exigences. Ici, tout reste dans la console locale. Lorsque ces fonctions passent leurs essais, nous pourrons les brancher sur les saisies et les messages de la dernière étape sans changer leur sens.

## Exemple guidé 1

```javascript
function compterVrais(resultats){
 let score=0;for(const ok of resultats){if(ok===true)score++;}
 return score;
}
console.log(compterVrais([true,false,true]));
```

## Exemple guidé 2

```javascript
function pourcentage(score,total){
 if(total===0)return null;
 return Math.round(score*100/total);
}
console.log(pourcentage(2,3));
console.log(pourcentage(0,0));
```
