## Explication pas à pas

Notre projet final est un questionnaire local dans la console. Il permet de s’entraîner avec des questions fictives, puis présente un bilan simple. Nous allons séparer les données, les calculs et le dialogue avec la personne. Cette séparation est utile même dans un petit programme : on peut vérifier la correction d’une réponse sans devoir rejouer toute une conversation à chaque essai.

Chaque question est un objet contenant un identifiant id, un énoncé enonce et une réponse attendue reponse. Le tableau de questions conserve leur ordre. Les noms de propriétés décrivent un contrat commun : toutes les fiches doivent utiliser les mêmes noms. Une propriété facultative categorie permettra de regrouper les questions, mais le premier atelier commence avec les trois propriétés indispensables. Les données proposées sont pédagogiques et ne proviennent d’aucun examen officiel.

Une réponse textuelle peut varier sans changer son sens pour notre règle limitée : des espaces avant ou après, ou des majuscules. Nous choisissons normaliser(texte), qui applique trim puis toLowerCase. Ainsi " OUI " et "oui" deviennent identiques. Cette règle ne traduit rien, ne retire pas les accents et ne juge pas une phrase libre. Pour une réponse comme "école", le mot "ecole" reste différent dans ce projet. Il faut annoncer cette limite au lieu de promettre une compréhension automatique.

La fonction estCorrecte(question,reponse) compare les deux textes normalisés et renvoie un booléen. Elle ne modifie pas la fiche question et n’affiche aucun message. L’appelant pourra compter les résultats ou choisir un retour en français. Le projet ne demande aucune IA : une comparaison suivant une convention explicite est plus prévisible qu’un service externe pour ces réponses courtes.

Prépare maintenant un jeu de données minimal avec deux questions dont les réponses sont différentes. Une collection où toutes les réponses seraient identiques pourrait laisser passer une comparaison incorrecte. Essaie une bonne réponse, une mauvaise, une version entourée d’espaces et un texte vide. Vérifie aussi que l’objet original conserve son énoncé et sa réponse après l’appel. Ces essais serviront encore lorsque nous ajouterons le score.

Un projet grandit par petits éléments vérifiables. N’ajoute pas encore de saisies ni de boucle principale : termine le modèle et les fonctions de comparaison, puis contrôle leurs résultats. À la fin de cette étape, tu disposes d’un cœur de correction réutilisable. La prochaine leçon traitera plusieurs réponses et un bilan ; la dernière branchera la conversation et les messages, sans changer les règles déjà testées.

## Exemple guidé 1

```javascript
const question={id:"q1",enonce:"Langage de styles ?",reponse:"CSS"};
function normaliser(texte){return texte.trim().toLowerCase();}
console.log(normaliser(question.reponse));
```

## Exemple guidé 2

```javascript
function normaliser(texte){return texte.trim().toLowerCase();}
function estCorrecte(question,reponse){
 return normaliser(question.reponse)===normaliser(reponse);
}
console.log(estCorrecte({reponse:"CSS"}," css "));
console.log(estCorrecte({reponse:"CSS"},"HTML"));
```
