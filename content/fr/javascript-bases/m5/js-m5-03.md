## Explication pas à pas

Une fiche peut être complète, partielle ou introuvable. Le programme doit traiter ces états sans inventer une information. Dans nos objets simples, lire une propriété qui n’existe pas renvoie undefined. Cette valeur ne signifie pas zéro. Elle n’a pas non plus le même rôle que null, que nous avons choisi explicitement pour une recherche sans résultat. Donner un sens à ces marqueurs fait partie du contrat des données.

Pour distinguer une quantité absente d’une quantité nulle, compare la propriété à undefined. Un stock ayant quantite:0 indique zéro unité ; un stock sans cette propriété indique une quantité inconnue. Un test comme if (stock.quantite) confond les deux car zéro est une valeur fausse dans ce contexte booléen. false et une chaîne vide ont également ce comportement. Il faut donc demander exactement ce que la règle veut savoir, plutôt que traiter toutes les valeurs fausses comme des absences.

Lire une propriété d’un objet partiel peut donner undefined ; lire une propriété de null ou de undefined provoque en revanche une erreur. Après une recherche, vérifie d’abord trouve !== null avant de lire trouve.titre. L’opérateur && évalue la seconde expression seulement si la première permet de poursuivre dans ce contexte. Cette évaluation courte permet d’écrire une garde, mais des blocs if successifs restent parfois plus simples à expliquer. La clarté compte davantage que la brièveté.

Une propriété présente peut encore contenir un type inattendu. typeof valeur permet de reconnaître ici une chaîne avec "string" ou un nombre avec "number". Ce contrôle ne valide pas toute la donnée : NaN appartient au type number, et Number.isFinite reste utile pour une quantité numérique finie. Autre particularité à retenir sans la généraliser : typeof null produit "object". Tester ce seul résultat n’autorise donc pas à utiliser null comme une fiche.

Les activités annoncent des ensembles de données limités : objets simples, marqueurs connus et valeurs fictives. Elles ne demandent pas une validation universelle de tous les objets JavaScript ni une protection complète contre des données externes. Prépare trois essais : donnée connue, valeur zéro et donnée absente. Ajoute une recherche sans correspondance. Trace la garde qui empêche l’accès trop tôt et le message choisi. Un bon résultat dit clairement ce qui est inconnu ; il ne remplace pas silencieusement une absence par une valeur qui semblerait réelle.

## Exemple guidé 1

```javascript
const stock = { quantite: 0 };
if (stock.quantite !== undefined) {
  console.log(stock.quantite);
} else { console.log("Inconnu"); }
```

## Exemple guidé 2

```javascript
const trouve = null;
if (trouve !== null && trouve.titre !== undefined) {
  console.log(trouve.titre);
} else { console.log("Introuvable"); }
```
