## Explication pas à pas

Un tableau permet de ranger une série de valeurs par position. Pour décrire un atelier, les positions deviennent moins parlantes : le premier élément serait le titre, le deuxième les places et le troisième l’ouverture. Un objet regroupe ces informations avec des noms de propriétés. La fiche { titre: "Semis", places: 4, ouvert: true } associe ainsi trois noms à trois valeurs de types différents. Les données du jardin restent fictives.

Une propriété s’écrit avec son nom, deux-points puis sa valeur. Les virgules séparent les propriétés dans les accolades. Le point permet de lire un nom connu : atelier.places donne la valeur de places. Le nom placé après le point n’est pas une variable à rechercher. Lorsque le nom de la propriété vient d’une variable, utilise les crochets : atelier[cle]. Si cle contient le texte "titre", cette écriture lit le titre. atelier.cle chercherait au contraire une propriété nommée littéralement cle.

Une affectation peut modifier une propriété existante, par exemple atelier.places = atelier.places - 1. Elle peut aussi ajouter une propriété. La déclaration const empêche de réaffecter le nom atelier à une autre valeur ; elle ne rend pas toutes les propriétés de l’objet immuables. Il est donc possible de mettre à jour atelier.places lorsque atelier a été déclaré avec const. Cette distinction deviendra importante lorsque tu voudras préserver des données d’origine.

Avec const copie = atelier, aucun nouvel objet indépendant n’est construit. Les deux noms donnent accès au même objet. Modifier copie.places est alors visible à travers atelier.places. On parle ici de référence partagée. Pour obtenir une copie indépendante de notre fiche simple, crée un autre objet et recopie explicitement ses propriétés. Les fiches utilisées dans cette leçon contiennent seulement des textes, nombres et booléens ; les objets imbriqués demanderont une distinction supplémentaire plus tard.

Avant chaque mise à jour, prédis les valeurs visibles à travers tous les noms concernés. Trace une colonne pour la valeur avant, une pour l’instruction et une pour la valeur après. Dans les exercices, les tests inspectent la fiche et pas seulement son affichage : écrire la bonne phrase sans construire les propriétés demandées ne suffit pas. Garde des noms cohérents et une seule règle de mise à jour à la fois. Termine en expliquant si ton code modifie la fiche d’origine ou construit une nouvelle fiche, et pourquoi ce choix correspond à la consigne.

## Exemple guidé 1

```javascript
const atelier = { titre: "Semis", places: 4, ouvert: true };
console.log(atelier.titre);
atelier.places = atelier.places - 1;
console.log(atelier.places);
```

## Exemple guidé 2

```javascript
const original = { titre: "Compost", places: 6 };
const autreNom = original;
autreNom.places = 5;
const cle = "places";
console.log(original[cle]);
```
