## Explication pas à pas

Un programme utilise parfois une entrée fournie par une personne ou une autre partie du code. Même dans un exercice local, cette entrée peut ne pas correspondre au contrat. Une quantité de fiches doit par exemple être un entier positif ou nul. Un texte vide, un nombre négatif et une décimale posent trois problèmes différents. Une validation explicite distingue ces situations avant de faire un calcul qui aurait l’air plausible.

Dans une fonction, on peut commencer par des gardes : si un critère est invalide, return fournit un résultat convenu puis termine l’appel. Dans ce chapitre, certaines fonctions renvoient null pour signaler l’échec. null est une valeur précise, différente de zéro et d’une chaîne vide. L’appelant doit vérifier ce signal avant de traiter le résultat comme un nombre. Ce choix fait partie du contrat, pas d’une règle universelle du langage.

Pour convertir un texte numérique, contrôle d’abord son type si le contrat l’exige, puis les espaces avec trim. Une chaîne vide ne doit pas devenir automatiquement une quantité zéro. Number donne un nombre à partir du texte ; Number.isFinite exclut NaN et les infinités. Number.isInteger impose ensuite un entier si la quantité représente des unités indivisibles. Ces contrôles ont des rôles distincts et se combinent avec && ou des retours anticipés.

JavaScript permet aussi de lancer une exception avec throw. Une instruction comme throw new Error("quantité invalide") interrompt le chemin normal. try puis catch permettent à un appelant de réagir à une exception. Nous les observons ici sans les utiliser comme raccourci pour accepter toute donnée. Un catch vide qui renvoie toujours zéro peut dissimuler un mauvais nom de variable ou un défaut de calcul qui demandait une correction.

Choisis une seule convention d’erreur par fonction et documente-la. Si lireQuantite renvoie null, teste exactement resultat === null. Un test général !resultat confondrait null avec zéro, alors que zéro peut être une quantité autorisée. Les messages destinés à une personne doivent être lisibles ; les valeurs destinées à une autre fonction doivent rester faciles à tester sans dépendre de la formulation du message.

L’atelier n’échange ici aucune donnée avec un serveur. La validation étudiée représente des règles de calcul, sans prétendre sécuriser à elle seule une application réelle. Prépare des essais valides et invalides, vérifie que les données initiales restent inchangées, puis compose ta fonction avec les calculs précédents. Lorsqu’un résultat t’étonne, commence par identifier si l’entrée a été acceptée ou refusée avant d’accuser l’opération suivante.

## Exemple guidé 1

```javascript
function lireQuantite(texte){
  if(texte.trim()==="")return null;
  const n=Number(texte);
  if(!Number.isInteger(n)||n<0)return null;
  return n;
}
console.log(lireQuantite("0"));
console.log(lireQuantite("mot"));
```

## Exemple guidé 2

```javascript
function verifier(n){
  if(n<0)throw new Error("Valeur négative");
  return n;
}
try{console.log(verifier(-1));}
catch(erreur){console.log(erreur.message);}
```
