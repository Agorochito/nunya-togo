## Explication pas à pas

Une fonction ne se résume pas à son exemple principal. Son contrat précise les entrées acceptées, le résultat renvoyé et les effets permis. Avant de coder un plafond de places, écris par exemple : pour un entier positif ou nul, renvoyer le nombre de places retenu, limité à quatre. Les tests découlent ensuite de cette règle ; ils ne doivent pas être choisis uniquement parce que le programme actuel les réussit.

Sépare les entrées en familles utiles. Pour un plafond de quatre, essaie zéro, une valeur intérieure comme deux, exactement quatre et une valeur au-dessus comme sept. Ces essais vérifient des chemins différents. Les valeurs juste aux limites sont particulièrement utiles : un signe strictement inférieur peut rejeter la borne attendue, alors qu’un signe inférieur ou égal la conserve. Le contrat indique lequel utiliser.

Prévois aussi la taille des collections. Une somme ou un filtre doit souvent fonctionner sur un tableau vide, un seul élément puis plusieurs éléments. Si la fonction promet de conserver l’ordre, choisis des valeurs différentes afin qu’une inversion soit visible. Si elle promet de ne pas modifier l’entrée, examine l’original après l’appel. Un tableau retourné correct ne suffit pas à prouver que la donnée de départ est restée intacte.

Comparer un tableau à un autre avec === ne compare pas leurs éléments : cela vérifie leur identité. Deux tableaux construits séparément sont des objets différents, même s’ils contiennent les mêmes nombres. Pour une comparaison simple de nombres dans ce cours, on peut vérifier les longueurs puis chaque position dans une boucle. Ce choix limité est explicite ; il ne constitue pas une fonction universelle pour comparer n’importe quel objet complexe.

Un test doit être compréhensible lorsqu’il échoue. Note l’entrée, l’attendu et l’observé. Ne modifie pas l’attendu pour faire disparaître une différence avant d’avoir relu le contrat. Une erreur peut se trouver dans le programme ou dans le test. Recalcule d’abord l’exemple à la main. Les exercices à venir utilisent des données fictives et des résultats reproductibles, sans dépendre de l’heure ni d’un service réseau.

Les tests donnent des indices solides sur les cas essayés, jamais une preuve automatique de toute propriété possible. Cherche un contre-exemple : une entrée qui respecte le contrat mais fait échouer ton raisonnement. Garde les cas révélateurs lorsque tu améliores le code. Cette habitude transforme le débogage en une démarche observable : annoncer une règle, préparer les essais, corriger, puis vérifier que les essais restent satisfaits.

## Exemple guidé 1

```javascript
function plafonner(n){ return n>4?4:n; }
for(const n of [0,2,4,7]){
  console.log(n,plafonner(n));
}
```

## Exemple guidé 2

```javascript
function memesNombres(a,b){
  if(a.length!==b.length){return false;}
  for(let i=0;i<a.length;i++){if(a[i]!==b[i]){return false;}}
  return true;
}
console.log(memesNombres([2,5],[2,5]));
console.log(memesNombres([2,5],[5,2]));
```
