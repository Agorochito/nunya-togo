## Explication pas à pas

Un programme peut s’arrêter avant de produire le résultat attendu. Ce n’est pas une note sur ta capacité : le moteur décrit un obstacle précis. Nous distinguons une erreur de syntaxe, qui empêche de lire le programme, une erreur pendant l’exécution, et un résultat logique incorrect sans arrêt. Cette distinction aide à choisir la première action utile plutôt que de modifier plusieurs lignes au hasard.

Une SyntaxError peut venir d’une parenthèse ou d’une accolade manquante. Lis le voisinage du numéro de ligne indiqué, y compris la ligne précédente : le moteur remarque parfois le manque lorsqu’il rencontre la suite. Une ReferenceError signale notamment un nom inconnu. Vérifie son orthographe, sa casse et l’endroit de sa déclaration. Une TypeError peut apparaître lorsqu’on appelle une méthode sur une valeur qui ne permet pas cette opération.

Commence par reproduire le problème avec une petite entrée. Note ce que tu attendais et ce que tu observes réellement. Pour une fonction de réduction, écris par exemple montant 1000, réduction 10, résultat attendu 900. Si tu observes 990, le calcul a probablement soustrait un pourcentage comme s’il s’agissait d’un montant. Le moteur n’a pas de raison de refuser cette opération : c’est notre règle métier qui est mal représentée.

Une trace est une suite d’observations des valeurs intermédiaires. Ajoute temporairement un console.log après la conversion, après le calcul du taux puis avant le retour. Indique un libellé avec la valeur pour éviter de confondre trois nombres. Dans les exercices, retire ces traces supplémentaires avant de vérifier une sortie qui doit être exacte ; les appels de contrôle des fonctions attendent aussi l’absence d’affichages parasites.

Change une seule cause supposée, puis relance le cas qui échouait. Ensuite, rejoue un cas qui fonctionnait déjà : une correction peut réparer un résultat et en casser un autre. Garde une courte note du défaut et de l’essai qui le révèle. Ce cas deviendra un test de régression, c’est-à-dire une vérification qui empêche le même défaut de revenir discrètement après une modification.

Évite de cacher un problème en renvoyant toujours zéro ou en affichant directement le résultat attendu. Cela donne une sortie correcte sur un exemple mais ne répare pas la règle. Le contrat d’une fonction porte sur plusieurs entrées. Nous allons corriger des noms, des calculs et un emplacement de return, puis vérifier des valeurs différentes pour distinguer une réparation générale d’un contournement ponctuel.

## Exemple guidé 1

```javascript
function total(prix,quantite){
  const montant=prix*quantite;
  return montant;
}
console.log(total(250,3));
```

## Exemple guidé 2

```javascript
function apresRemise(prix,taux){
  const reduction=prix*taux/100;
  return prix-reduction;
}
console.log(apresRemise(1000,10));
```
