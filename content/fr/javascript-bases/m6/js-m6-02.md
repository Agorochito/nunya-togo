## Explication pas à pas

Une réservation fictive peut demander plusieurs calculs : prix des places, réduction puis ajout d’un forfait. Une fonction longue peut tout faire, mais des étapes nommées rendent les règles plus faciles à lire. La composition consiste ici à appeler une fonction, récupérer son retour puis fournir ce résultat à une autre. Le traitement reste synchrone : aucun serveur, aucune attente et aucune promesse ne sont nécessaires pour ce cours.

Commence par définir le rôle de chaque étape. prixLigne(prix,quantite) retourne une multiplication. appliquerRemise(montant,taux) retourne un montant réduit. montantFinal peut appeler ces deux traitements puis ajouter un forfait. Des variables intermédiaires comme brut et reduit rendent l’ordre visible. Une écriture imbriquée peut être équivalente, mais elle n’est utile que si tu peux encore expliquer les arguments et le résultat de chaque appel.

L’ordre des opérations exprime une règle de domaine. Appliquer dix pour cent de remise sur cent, puis ajouter cinq, donne quatre-vingt-quinze. Ajouter cinq avant la remise donne quatre-vingt-quatorze et demi. Les deux calculs sont possibles mathématiquement ; un seul respecte notre contrat. Écris donc la règle en français avant le programme. Un test avec une remise nulle peut manquer cette erreur, alors qu’un test où les trois étapes contribuent la révèle.

Un calcul pur produit, pour les mêmes arguments autorisés, le même résultat sans modifier les données qui lui sont fournies ni des variables extérieures. Il ne lit pas une nouvelle saisie et n’affiche pas de message pendant le calcul. Cela facilite les essais répétés et la réutilisation. Une fonction qui accumule ses résultats dans une variable globale peut fonctionner au premier appel et dériver au suivant. Place les valeurs temporaires dans le contexte local de l’appel.

Le résultat peut être un nombre, un booléen ou un objet construit pour résumer plusieurs informations. Une fonction bilan peut retourner les places restantes et l’état complet, sans changer la capacité ou le nombre d’inscrits. Les exercices appellent plusieurs fois les fonctions, puis vérifient des données extérieures quand c’est pertinent. Il ne s’agit pas d’interdire tous les effets dans toute application : lire et afficher restent utiles, mais ils doivent être identifiés. Pour ces contrats de calcul, séparer les effets permet de comprendre exactement d’où vient chaque réponse.

## Exemple guidé 1

```javascript
function prixLigne(prix, quantite) { return prix * quantite; }
function appliquerRemise(montant, taux) { return montant - montant * taux / 100; }
function montantFinal(prix, quantite, taux, forfait) {
  const brut = prixLigne(prix, quantite);
  const reduit = appliquerRemise(brut, taux);
  return reduit + forfait;
}
console.log(montantFinal(20, 3, 10, 5));
```

## Exemple guidé 2

```javascript
function restantes(capacite, inscrits) { return capacite - inscrits; }
function bilan(capacite, inscrits) {
  const libres = restantes(capacite, inscrits);
  return { restantes: libres, complet: libres === 0 };
}
const resultat = bilan(8, 8);
console.log(resultat.restantes);
console.log(resultat.complet);
```
