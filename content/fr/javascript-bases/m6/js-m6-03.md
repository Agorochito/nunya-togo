## Explication pas à pas

Le jardin souhaite montrer une projection du nombre de places sans modifier son programme d’origine. Une fonction qui reçoit un tableau peut le parcourir, mais elle peut aussi modifier ses objets si elle réutilise leurs références. Le fait de déclarer le paramètre ou le résultat avec const ne suffit pas à l’empêcher. Pour une transformation sans mutation, il faut construire les valeurs qui changent à un endroit indépendant de celles reçues.

Une nouvelle paire d’accolades crée un nouvel objet. L’écriture { ...fiche, places:0 } recopie les propriétés propres énumérables de fiche dans un nouvel objet, puis donne zéro à places. Ce mécanisme de décomposition est une copie superficielle : si une propriété contient elle-même un objet, la référence de cet objet reste partagée. Nos contrats se limitent à des fiches plates contenant textes, nombres et booléens. Ils ne promettent donc pas une copie indépendante de toute profondeur.

Pour transformer un tableau de fiches, commence avec un tableau vide. Parcours les entrées et ajoute un nouvel objet pour chaque sortie voulue. Ajouter directement la fiche d’origine construit un nouveau tableau mais partage encore la fiche. Deux questions sont donc distinctes : le tableau résultat est-il nouveau, et ses objets le sont-ils aussi ? Un essai utile consiste à modifier une propriété d’un objet retourné puis à vérifier que la fiche d’origine reste inchangée.

Le contrat doit annoncer l’ordre, les doublons et le tableau vide. Dans notre sélection, les fiches retenues conservent leur ordre ; deux fiches ayant le même id ne sont pas fusionnées. Un minimum de places inclus utilise >=. Dans un bilan numérique, une collection vide possède un total de zéro et un nombre d’éléments nul. Nous choisissons moyenne:null pour signaler l’absence de moyenne, plutôt que retourner un résultat de division non valable ou inventer une observation.

Les tests de cette leçon vérifient le retour, plusieurs cas limites et la conservation des arguments. Les nombres admis sont finis et non négatifs ; les fiches possèdent les propriétés annoncées. La gestion de toutes les formes d’objets inconnus reste hors du contrat. Avant de coder, écris trois lignes : ce que reçoit la fonction, ce qu’elle retourne et ce qu’elle doit préserver. Après les essais, explique la différence entre une copie superficielle suffisante pour ces données et une copie profonde qui serait nécessaire avec d’autres structures. Cette précision évite de transformer une solution locale correcte en promesse trop générale.

## Exemple guidé 1

```javascript
function fermerFiche(fiche) {
  return { ...fiche, ouvert: false };
}
const original = { titre:"Semis", ouvert:true };
const ferme = fermerFiche(original);
console.log(original.ouvert);
console.log(ferme.ouvert);
```

## Exemple guidé 2

```javascript
function bilanPlaces(fiches) {
  let total = 0;
  for (const fiche of fiches) { total = total + fiche.places; }
  if (fiches.length === 0) { return { total:0, moyenne:null }; }
  return { total:total, moyenne:total / fiches.length };
}
const resultat = bilanPlaces([]);
console.log(resultat.total);
console.log(resultat.moyenne === null);
```
