## Explication pas à pas

Un programme peut calculer une réponse à une question. La comparaison 4 < 7 demande si quatre est strictement inférieur à sept ; son résultat est true. Cette valeur appartient au type booléen, qui comporte aussi false. Les mots restent en anglais dans le code, mais nous les lisons comme vrai et faux. Une comparaison n’affiche rien seule : console.log permet d’observer son résultat.

Les opérateurs < et > expriment une inégalité stricte. Les signes <= et >= incluent la valeur limite. Pour vérifier si une boîte peut contenir une quantité demandée, demande <= capacite accepte aussi une quantité exactement égale à la capacité. Le choix du signe traduit une règle ; il ne doit pas être décidé au hasard après l’échec d’un test.

L’égalité stricte s’écrit ===. Elle compare des valeurs sans convertir automatiquement leurs types. Le nombre 5 et le texte "5" sont donc différents. Le signe !== vérifie une différence stricte. Cette écriture aide à rendre le contrat clair : veut-on comparer des textes saisis, ou des nombres déjà convertis ? Applique les conversions voulues avant la comparaison, pas pour masquer une mauvaise donnée.

Ne confonds pas === avec =. Le premier pose une question ; le second affecte une valeur. Une comparaison peut être conservée dans une variable : const complet = places === 0. Le nom complet contient alors un booléen et non le nombre de places. Un nom de ce type doit faire comprendre la question représentée. Il pourra bientôt guider une condition.

Pour vérifier une limite, prépare plusieurs cas : une valeur juste avant, une valeur égale et une valeur juste après. Si une règle accepte au maximum dix éléments, neuf et dix doivent convenir, mais onze doit être refusé. Cette petite table évite de tester uniquement un exemple facile situé loin de la frontière. Elle relie le symbole choisi au sens de la consigne.

Nos comparaisons portent sur des valeurs simples, nombres ou chaînes. Nous ne comparons pas encore des objets ou des tableaux, qui demandent d’autres distinctions. Les affichages true et false ne constituent pas une note ou un jugement sur une personne : ils décrivent seulement le résultat d’un test précis. Explique toujours quelle question a été évaluée avant d’interpréter le booléen.

## Exemple guidé 1

```javascript
const places = 0;
const complet = places === 0;
console.log(complet);
```


## Exemple guidé 2

```javascript
const texte = "5";
console.log(texte === 5);
console.log(Number(texte) === 5);
```
