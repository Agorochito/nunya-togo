## Explication pas à pas

Une règle utile comporte souvent plusieurs critères. Une quantité peut devoir être présente, être un nombre fini et rester entre deux bornes. Chaque question donne un booléen. L’opérateur && signifie et : les deux conditions doivent être vraies. L’opérateur || signifie ou : au moins une des conditions doit être vraie. Le signe ! inverse un booléen. Les parenthèses aident à montrer le groupement choisi.

Pour vérifier une plage fermée de un à cinq, nombre >= 1 && nombre <= 5 exprime les deux limites. Tester seulement la première laisse passer des valeurs trop grandes ; tester seulement la seconde laisse passer des valeurs trop petites. Choisis des essais juste en dessous, exactement aux bornes et juste au-dessus. Les nombres décimaux restent autorisés à moins qu’une règle supplémentaire ne les exclue.

Number.isInteger vérifie qu’une valeur est un nombre entier. Si un compteur représente des fiches complètes, le contrat peut exiger un entier ; si une durée accepte des fractions de minute, il peut ne pas l’exiger. La validation n’est pas une liste universelle à copier. Elle doit représenter la donnée demandée. Énonce cette règle dans la consigne avant de programmer et avant de tester.

Le texte reçu mérite un contrôle distinct. Après trim, une chaîne vide signifie qu’aucun contenu n’a été fourni. Ce test doit être conservé même si Number transforme cette chaîne en zéro. Pour certaines réponses textuelles, toLowerCase produit une version en minuscules : "OUI" devient "oui". Ce nettoyage ne traduit pas les mots et ne supprime pas les accents ; il applique seulement la transformation annoncée.

Avec else if, on peut enchaîner plusieurs choix. Le moteur examine les tests dans l’ordre et prend la première branche vraie. Une branche finale else couvre ce qui reste. Une règle large placée trop tôt peut masquer une règle plus précise. Pour classer des scores, commence donc par écrire les catégories sans chevauchement, puis vérifie qu’un score situé sur une frontière n’a qu’une interprétation.

Garde la validation et le message lisibles. Une expression très longue est parfois moins claire qu’un booléen nommé, comme dansPlage ou entier. Ces noms décrivent des questions, sans inventer une garantie générale. Accepter un nombre ne prouve pas qu’une donnée réelle est exacte : ici nous vérifions uniquement le contrat d’exercices à valeurs fictives, sans transmettre quoi que ce soit à un service extérieur.

## Exemple guidé 1

```javascript
const n=Number(input("Entier de 1 à 5 ?"));
const valide=Number.isInteger(n)&&n>=1&&n<=5;
console.log(valide);
```


## Exemple guidé 2

```javascript
const reponse=input("Oui ou non ?").trim().toLowerCase();
if(reponse==="oui"){console.log("Accord");}
else if(reponse==="non"){console.log("Refus");}
else{console.log("À préciser");}
```
