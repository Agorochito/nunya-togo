## Explication pas à pas

Une erreur logique produit un comportement différent du besoin alors que Python comprend les instructions. Le programme peut terminer normalement et donner une réponse plausible. Pour une moyenne, diviser par le nombre plus un évite parfois une erreur technique mais crée un résultat faux. Pour une condition inclusive, utiliser un signe strict refuse silencieusement la frontière. Le message de la console ne suffit donc pas à dire que le traitement est juste.

Formule une hypothèse à partir d’un cas qui échoue. Si une sélection oublie toujours la dernière valeur, examine les bornes du parcours. Si une recherche ne trouve que le premier élément, regarde où se trouve return False. Si un total vaut seulement la dernière quantité, vérifie si l’affectation conserve l’ancien total. Chaque hypothèse relie un symptôme à une règle d’exécution que nous savons tracer.

Un cas de régression est un exemple que l’on rejoue après une réparation pour empêcher le retour d’un défaut connu. Conserve au moins le cas qui révélait le problème et un cas auparavant correct. Une modification de frontière peut réparer l’égalité tout en cassant le reste si l’on a inversé le sens de la comparaison. Le but n’est pas de changer jusqu’à obtenir du vert, mais d’expliquer pourquoi la nouvelle règle convient à tous les cas annoncés.

Les exercices reprennent des fonctions courtes pour rendre ce raisonnement visible. Le contrat reste la référence ; le code initial n’est qu’une tentative. Écris une phrase décrivant le défaut, une phrase décrivant la réparation, puis une prévision sur un nouvel exemple. Cette petite explication est un outil de compréhension, même lorsqu’elle n’est pas notée automatiquement par la plateforme.

Les activités appliquent ces règles dans quatre situations complémentaires. La trace des sommes successives explique la réparation. Plusieurs valeurs différentes détectent l’oubli du passé, tandis que le vide confirme la bonne initialisation. Le cas trouvé en fin de liste sert de régression contre un arrêt trop tôt. La recherche ne conclut à l’absence qu’après avoir examiné toute la collection. Une liste avec deux réussites vérifie que le compteur dépasse un. Le cas mixte contrôle en plus la frontière inclusive et l’exclusion des valeurs trop petites. Le contrat non vide autorise directement la division. Un seul élément doit retrouver sa propre valeur, ce qui révèle rapidement un dénominateur augmenté par erreur.

Pour réparer un programme, garde une copie de l’idée de départ et formule une hypothèse précise. Modifie une seule cause à la fois, puis relance le cas qui révélait le problème. Rejoue aussi un ancien cas correct pour vérifier que la réparation ne le casse pas. Un résultat affiché sans message d’erreur peut encore être faux : les tests vérifient le besoin, pas seulement l’absence d’arrêt.

## Exemple guidé 1

```python
def total(valeurs):
    resultat = 0
    for valeur in valeurs:
        resultat = resultat + valeur
    return resultat
print(total([2, 5, 3]))
```
