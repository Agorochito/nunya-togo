## Explication pas à pas

Un besoin comporte souvent plusieurs règles qui ne doivent pas être mélangées immédiatement. Pour calculer un devis fictif, une règle détermine le montant brut, une autre la remise et une dernière la disponibilité des places. Commence par nommer ces capacités et leurs contrats. Chaque petite fonction reçoit seulement les informations dont elle a besoin et transmet un résultat clairement défini.

La décomposition aide à localiser une erreur. Si le montant brut est correct mais le total final faux, vérifie la transformation de remise avant de relire toutes les lignes. On peut exécuter chaque fonction sur un exemple simple, puis tester leur combinaison. Le programme de combinaison n’a pas besoin de connaître les variables locales des fonctions appelées : il utilise leurs retours. Les paramètres sont les points d’entrée et les retours sont les sorties.

Il ne faut pas découper sans raison. Une fonction appelée calculer qui contient une opération mystérieuse n’aide pas autant qu’un nom précisant la règle. Inversement, plusieurs fonctions très courtes peuvent être utiles si chacune correspond à une décision réutilisée et vérifiable. L’objectif est de réduire la difficulté du raisonnement, pas de maximiser le nombre de définitions.

Dans cette leçon, les données respectent les types et limites annoncés. Le calcul de remise reste un exercice numérique sans règle monétaire réelle. Pour le devis total, les frais fixes ne subissent pas la remise : on réduit seulement le prix multiplié par le nombre. L’ordre est donc important. Écris un exemple avec des frais non nuls pour voir la différence entre réduire le sous-total et réduire toute la facture. Les contrats des petites fonctions doivent rester compatibles avec celui de la combinaison.

Les activités appliquent ces règles dans quatre situations complémentaires. Le montant brut est une règle indépendante de la remise et des frais. La tester seule permet de repérer un défaut avant de combiner plusieurs décisions. La somme représente un coût fixe distinct du nombre d’articles. Les frais restent présents même lorsque le montant initial vaut zéro, selon le contrat choisi. L’ordre des étapes traduit une règle commerciale fictive explicite. Réduire les frais aussi donnerait un autre résultat, détecté par les cas où ils sont non nuls. Une décision de disponibilité est distincte du calcul de prix. Le cas exactement complet est accepté, tandis qu’une demande négative reste refusée même si la somme paraît petite.

Écris tes prévisions avant de consulter les résultats. Pour chaque cas, note les entrées, les étapes utiles et la réponse attendue. Choisis aussi une entrée différente de celles de l’exemple guidé. Si une règle manque dans une consigne réelle, il faut la clarifier plutôt que deviner ; ici, les contrats précisent les limites. Une solution courte et explicable vaut mieux qu’une accumulation de conditions sans lien avec le besoin.

## Exemple guidé 1

```python
def brut(prix, nombre):
    return prix * nombre
def reduire(montant, taux):
    return montant - montant * taux / 100
print(reduire(brut(20, 3), 10))
```

## Exemple guidé 2

```python
def devis(prix, nombre, frais):
    sous_total = prix * nombre
    return sous_total + frais
print(devis(20, 3, 5))
```
