## Explication pas à pas

Une fonction peut réussir un exemple et rester incorrecte. Un programme qui retourne toujours dix passera le cas dont la bonne réponse vaut dix. Pour vérifier une capacité, les exemples doivent varier les informations qui commandent le résultat. Pour un filtre, essaie une valeur acceptée et une valeur refusée. Pour une collection, essaie le cas vide, un élément et plusieurs éléments différents. Pour une borne, vérifie la valeur exacte ainsi que ses voisines.

On peut aussi utiliser une propriété simple. Ajouter zéro à une somme ne devrait pas changer le total. Dupliquer chaque élément d’une liste devrait doubler sa somme, même si nous ne connaissons pas immédiatement le résultat complet. Une telle relation ne remplace pas les exemples exacts, mais peut révéler un défaut que des valeurs trop semblables cachent. Il faut choisir une propriété qui découle réellement du contrat.

Un test raconte une attente : entrées fournies, résultat voulu et règle concernée. Les exercices du site ajoutent certains cas non affichés d’abord, mais leurs règles ne doivent jamais être secrètes. Si une fonction accepte une liste vide, cette possibilité doit être expliquée, même lorsque le test précis reste différent. Un test n’a pas le droit d’exiger discrètement un format ou une exception jamais annoncés.

Ne force pas une seule manière de coder quand plusieurs solutions répondent au besoin. Une boucle et un calcul direct peuvent convenir si aucune construction n’est imposée pour l’apprentissage. En revanche, un effet interdit, comme modifier la liste reçue, reste un échec même lorsque la valeur retournée est exacte. Nous vérifions donc le comportement observable, pas la ressemblance avec la correction. Note enfin ce qui n’a pas été vérifié : réussir ces cas ne constitue pas une preuve mathématique de tous les programmes possibles.

Les activités appliquent ces règles dans quatre situations complémentaires. Les voisins du seuil vérifient le changement de règle. La valeur zéro et une quantité plus grande empêchent de confondre la formule avec une réponse constante. Le cas entièrement blanc vérifie le nettoyage et les doublons vérifient que la fonction compte des réponses utiles, sans se transformer en déduplication non demandée. Un exemple seulement positif cacherait une initialisation erronée à zéro. Le cas vide possède ici une réponse explicite, None, distincte de tous les maxima numériques. Plusieurs solutions peuvent construire la sélection attendue. Les tests portent sur l’ordre, les frontières et la conservation de l’argument plutôt que sur une copie exacte de la correction.

Écris tes prévisions avant de consulter les résultats. Pour chaque cas, note les entrées, les étapes utiles et la réponse attendue. Choisis aussi une entrée différente de celles de l’exemple guidé. Si une règle manque dans une consigne réelle, il faut la clarifier plutôt que deviner ; ici, les contrats précisent les limites. Une solution courte et explicable vaut mieux qu’une accumulation de conditions sans lien avec le besoin.

## Exemple guidé 1

```python
def tarif(nombre):
    if nombre >= 5:
        return nombre * 8
    return nombre * 10
print(tarif(4))
print(tarif(5))
```

## Exemple guidé 2

```python
def somme(valeurs):
    total = 0
    for valeur in valeurs:
        total = total + valeur
    return total
print(somme([2, 5]))
print(somme([2, 5, 0]))
```
