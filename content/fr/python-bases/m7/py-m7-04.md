## Explication pas à pas

Une fonction utilise des noms pour recevoir ses arguments et organiser son calcul. Un nom créé par une affectation dans le bloc est local à cet appel. Il n’apparaît pas automatiquement dans le programme principal. Si une fonction calcule total puis le retourne, le programme principal doit recevoir ce retour dans son propre nom. Utiliser une variable locale après la fin de l’appel sans cette transmission provoque une erreur de nom.

La portée locale des noms ne signifie pas que les objets reçus sont copiés. Si le paramètre nombres désigne une liste, nombres.append(5) modifie cette liste, et le programme appelant observe la modification. Pour une fonction qui doit produire une version enrichie sans toucher à l’original, commence par une copie nombres[:]. Avec un dictionnaire plat, .copy() fabrique un autre dictionnaire contenant les mêmes associations. Ces copies restent superficielles ; nous utilisons ici des valeurs simples.

Le contrat doit annoncer les effets permis. Les fonctions de cette leçon retournent leur résultat sans modifier leurs arguments. Cette règle permet de réutiliser les mêmes données pour plusieurs calculs et de comparer l’avant et l’après. Les tests vérifient le résultat ainsi que la conservation des listes ou dictionnaires fournis. Une fonction qui retourne le bon nombre après avoir vidé l’argument ne satisfait donc pas la demande.

Une tâche peut être décomposée en plusieurs fonctions petites et nommées. Chaque fonction doit cependant avoir un rôle clair, pas simplement cacher une ligne incompréhensible. Commence par des calculs simples à tester isolément. Le programme principal décide ensuite de leur combinaison et de l’affichage. Évite les variables globales pour transmettre un calcul : les paramètres et les retours rendent les dépendances visibles et les essais indépendants.

Les activités appliquent ces règles dans quatre situations complémentaires. Le résultat est une liste distincte. Conserver les arguments évite que la préparation d’un affichage change silencieusement la liste partagée par le reste du programme. Une variable locale suffit pour construire le bilan. La fonction n’a pas besoin de supprimer les éléments ou de conserver une variable globale entre ses appels. La nouvelle association peut remplacer une clé ou en créer une. La copie protège l’inventaire d’origine pour que le programme puisse accepter ou abandonner la proposition. Le test de conservation révèle une modification que le seul affichage du résultat cacherait. La règle de pureté fait partie du contrat explicite de cette activité.

Avant chaque essai, distingue les informations fournies à l’appel et ce qui doit ressortir de la fonction. Une définition n’est pas une exécution. Suis l’ordre des instructions et le retour au programme appelant. Les valeurs des exercices sont fictives et respectent les limites annoncées. Les tests peuvent appeler la fonction avec plusieurs valeurs : une réponse écrite spécialement pour un exemple ne respecte pas le contrat général.

## Exemple guidé 1

```python
def avec_nom(noms, nouveau):
    copie = noms[:]
    copie.append(nouveau)
    return copie
base = ["Awa"]
print(avec_nom(base, "Jo"))
print(base)
```
