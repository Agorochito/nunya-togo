## Explication pas à pas

Une collection n’est pas choisie seulement parce qu’elle peut contenir les données. Elle doit rendre les opérations utiles simples à comprendre. Pour une file d’inscriptions fictive, la liste conserve l’ordre et les éventuelles répétitions. Pour une fiche de deux mesures dont les positions sont fixes, un tuple exprime ce regroupement. Pour retrouver une quantité par un nom, un dictionnaire rend l’association explicite. Pour savoir quels noms sont apparus au moins une fois, un ensemble élimine les répétitions inutiles.

La même enquête peut demander plusieurs vues. Une liste des réponses conserve les apparitions. Un ensemble des réponses mesure la diversité. Un dictionnaire de fréquences relie chaque réponse à son nombre d’apparitions. Transformer la liste en ensemble perd l’information sur les répétitions : aucune opération ne peut les reconstruire sans revenir aux réponses originales. Garde donc la donnée dont tu pourrais encore avoir besoin et crée des vues séparées.

Pour parcourir ensemble une clé et sa valeur, un dictionnaire propose items(). L’écriture for nom, nombre in comptes.items() déballera chaque paire. Pour présenter un bilan classé par clé, utilise for nom in sorted(comptes), puis lis comptes[nom]. Cette seconde forme garantit un ordre de sortie explicite pour nos codes simples. Le tri est une décision de présentation, pas une condition nécessaire au comptage.

Avant de coder, écris deux phrases : quelle information faut-il conserver, et quelle question doit être rapide à poser ? Vérifie ensuite le cas vide et un cas comportant une répétition. Une bonne modélisation évite des recherches ou des conditions inutiles. Aucun de ces récipients ne sauvegarde automatiquement ses données entre deux exécutions ; le travail sur les fichiers et les bases persistantes appartiendra au niveau suivant.

Les activités appliquent ces règles dans quatre situations complémentaires. Le dictionnaire conserve les fréquences tandis que le tri ne sert qu’à la présentation. Un code répété augmente une valeur existante au lieu d’ajouter une nouvelle clé. La liste initiale et l’ensemble répondent à des questions différentes. Garder les deux vues évite de perdre les apparitions tout en calculant le nombre de noms distincts. La liste de tuples garde l’ordre des fiches et le rôle de leurs positions. Le déballage permet ensuite d’écrire une condition lisible sur la capacité. La somme des fréquences reconstitue le nombre de réponses. Compter seulement les paires mesurerait les catégories distinctes et donnerait un autre indicateur.

Avant de choisir une collection, formule la question : faut-il conserver l’ordre, associer une valeur à un nom ou retenir des éléments distincts ? Dessine une petite représentation sur papier. Vérifie un exemple contenant une répétition et un autre sans donnée. Un résultat exact sur un seul exemple ne suffit pas à justifier le choix. Les collections restent en mémoire pendant l’exécution ; elles ne sont pas enregistrées dans un fichier.

## Exemple guidé 1

```python
reponses = ["A", "B", "A"]
comptes = {}
for code in reponses:
    comptes[code] = comptes.get(code, 0) + 1
for code in sorted(comptes):
    print(code, comptes[code])
```

## Exemple guidé 2

```python
comptes = {"A": 2, "B": 1}
total = 0
for code, nombre in comptes.items():
    total = total + nombre
print(total)
```
