## Explication pas à pas

Le projet final relie les contrôles de temps, de ressource et d’historique. La création reçoit un identifiant inédit, un équipement et un créneau. Elle refuse les bornes invalides, un identifiant déjà utilisé dans l’historique et un conflit avec une fiche active du même équipement. Une demande acceptée ajoute une nouvelle fiche active à la fin d’une nouvelle liste. Une demande refusée retourne None et conserve les données précédentes.

L’annulation est une autre opération : elle passe une fiche active à False dans une copie de l’historique. Son créneau est alors libre pour un autre identifiant. Le projet doit démontrer cette suite, pas seulement tester les fonctions isolées. Réserver un créneau, l’annuler puis réserver un chevauchement avec un nouvel identifiant doit réussir. Réutiliser l’ancien identifiant doit rester impossible.

La fonction de synthèse reçoit des demandes sous forme de dictionnaires. Le type reserver fournit toutes les informations de création ; annuler fournit seulement l’identifiant. Les types inconnus sont refusés. Chaque demande est examinée dans l’ordre et une demande refusée compte une fois. Les opérations déjà acceptées ne sont pas annulées : nous conservons la politique séquentielle utilisée pour l’inventaire.

Un petit dictionnaire de résultat rassemble l’historique final et le nombre de refus. Le programme appelant pourra ensuite présenter ce bilan, sans que les fonctions de gestion imposent un affichage particulier. Les fonctions auxiliaires sont fournies dans le dernier exercice pour que tu puisses concentrer ton raisonnement sur l’assemblage. Tu peux lire leurs contrats, les tester séparément et proposer une autre écriture respectant les mêmes comportements. Explique enfin les limites : journée unique, minutes entières, données fictives et stockage en mémoire uniquement.

Pour contrôler toutes les paires de fiches, une boucle peut contenir une autre boucle. La boucle extérieure choisit un indice i ; la boucle intérieure choisit j depuis i + 1 jusqu’à la fin. Ainsi, une fiche n’est pas comparée à elle-même et chaque paire est examinée une seule fois. Par exemple, avec trois fiches, les paires d’indices sont (0, 1), (0, 2) puis (1, 2). Applique ensuite à chaque paire les critères de conflit déjà étudiés.

Les activités appliquent ces règles dans quatre situations complémentaires. La création préserve les invariants du modèle. Les tests distinguent l’adjacence autorisée du conflit, puis séparent une ressource différente et un identifiant déjà utilisé. La vue d’agenda prouve que les fiches annulées ne sont plus des engagements. Leur présence dans l’argument reste utile à l’historique et à l’unicité des identifiants. Le contrôle examine un état complet au lieu d’une seule demande. Les boucles imbriquées parcourent chaque paire distincte et ignorent une fiche comparée à elle-même. La synthèse démontre toutes les règles du projet : adjacence, chevauchement, bornes, équipements indépendants, identités stables, annulation et absence de mutation des données reçues.

Les horaires sont des entiers représentant des minutes dans une seule journée fictive ; aucun fuseau ni changement de date n’intervient. Dessine les créneaux sur une ligne pour vérifier les frontières. Ne remplace pas les règles par une impression visuelle : le même équipement et l’état actif comptent aussi. Les fonctions retournent des données en mémoire et conservent leurs arguments. Un refus doit être explicable par le contrat annoncé.

## Exemple guidé 1

```python
def reserver(reservations, identifiant, equipement, debut, fin):
    if not (debut >= 0 and debut < fin and fin <= 1440):
        return None
    for r in reservations:
        if r["id"] == identifiant:
            return None
        if r["active"] and r["equipement"] == equipement and debut < r["fin"] and r["debut"] < fin:
            return None
    copie = []
    for r in reservations:
        copie.append(r.copy())
    copie.append({"id":identifiant, "equipement":equipement, "debut":debut, "fin":fin, "active":True})
    return copie

def annuler(reservations, identifiant):
    trouve = False
    for r in reservations:
        if r["id"] == identifiant and r["active"]:
            trouve = True
    if not trouve:
        return None
    copie = []
    for r in reservations:
        fiche = r.copy()
        if fiche["id"] == identifiant:
            fiche["active"] = False
        copie.append(fiche)
    return copie

historique = []
historique = reserver(historique, "r1", "A", 540, 600)
historique = annuler(historique, "r1")
historique = reserver(historique, "r2", "A", 550, 580)
print(len(historique))
print(historique[0]["active"])
print(historique[1]["active"])
```
