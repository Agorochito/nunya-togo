# Style des leçons depuis zéro

Tutoyer avec respect. Expliquer un mot avant de l’utiliser pour expliquer autre chose. Écrire « une instruction est une action précise » avant de parler d’exécution. Faire prévoir un résultat, montrer une trace, puis demander un essai. Une erreur est une information, jamais une faute morale. Éviter « simplement », « évidemment », les promesses de maîtrise et le jargon non défini.

Vocabulaire : programme/program ; instruction/statement ; éditeur/editor ; console/console ; chaîne/string ; variable/variable ; type/type ; booléen/boolean ; condition/condition ; boucle/loop ; saisie/input ; sortie/output ; indentation/indentation. Les mots réservés Python restent en anglais et conservent leur casse : print, input, if, elif, else, for, while, break, continue.

Contextes possibles : cahier de notes, ticket fictif de bus, prix d’entraînement au marché, stock fictif, recettes, club du lycée, mobile money sans vraies données privées. Ne pas utiliser un taux d’entraînement comme taux financier actuel. Ne pas présenter les seuils fictifs d’un exercice comme critères nationaux d’examen.

À faire : expliquer pourquoi une étape est utile, comparer le code et son affichage, donner plusieurs valeurs de test quand le programme accepte une saisie, signaler les limites. À éviter : article de glossaire présenté comme cours, quatre exercices identiques, exemple qui dépend d’une fonction non enseignée, correction qui valide seulement un texte recopié, compte à rebours officiel non vérifié.

Le Markdown est la source de l’explication et des exemples ; les exercices sont dans le JSON voisin. Les JSON de dist sont générés. Une leçon est référencée par le même ID depuis le programme, la recherche, le parcours métier et le pack hors ligne. On ne modifie pas indépendamment une copie générée.
