# Nunya — full review, competitive comparison and owner to-do list

Date: 4 November 2026 · Scope: the whole repository at branch `interface-5.2`, including the uncommitted 5.3/5.4 work, plus the live site and the Supabase project, read-only. Method: 6 parallel code reviews (AI assistant, front-end architecture, PWA/ops, content and pedagogy, onboarding and data, tests/docs/legal). Each high-severity finding was then checked by a separate verifier who tried to refute it. 33 verifications ran and none refuted a finding, though several severities were lowered. Five web-research tracks covered competitors, AI providers, funding, technical alternatives and Togolese law. Nothing in the repo was changed except adding this file.

## 1. Executive summary

**Where Nunya stands.** Nunya is more careful and more honest than most projects at this stage:
- The CSP is strict, and output is escaped consistently.
- AI answers cannot inject HTML.
- The quota is server-only, uses `SECURITY DEFINER` with an empty `search_path` and an advisory lock.
- Content is clearly labelled "brouillon".
- Third-party licences are attributed and machine-checked.
- Every Python solution is executed in CI.
- Lighthouse scores are 96/100/100.

No competitor we found combines French, offline-first use, in-browser Python, level-0 digital basics and Togo-specific exam material. That combination is a real niche.

**But it is not launch-ready for minors yet.** The blockers are mostly not about code quality:

## 3. Findings by area

Severity is the verified severity. File references point to the current working tree.

### 3.1 Security & privacy
- **High — Privacy page out of date for Nunya Aide** (`dist/academy.js` `privacyView`). It never mentions Supabase (EU, eu-west-3), Groq (US) or the anonymous session. Separately, the AI consent screen (`dist/aide-panel.js:125`) leaves out that data is processed in the US, Groq's abuse logging of up to 30 days, and that Supabase stores IP addresses.
- **High — One person can drain the 300/day global AI cap.** Anonymous sessions are free to create: about 30 per hour per IP × 15 questions each. Fix: Cloudflare Turnstile CAPTCHA on sign-up, plus a per-IP counter in the function and a reserved share of the budget.
- **Medium (lowered from critical) — Anonymous sessions can write to the 10 sync tables** (`supabase/migrations/001_nunya.sql:19-21`). Anonymous users get the `authenticated` role. RLS still limits each user to their **own** rows, so this is not a data leak, but anyone could fill the free 500 MB database with junk. Fix before enabling anonymous sign-ins: add a restrictive `is_anonymous` policy or revoke writes, add a `pg_column_size(payload)` check, and schedule cleanup of anonymous users with pg_cron. Email sign-up is a second way in; disable it until sync ships.
- **Medium — HTML injection through a crafted share link** (`dist/academy-app.js:29`). `href="${aRoute.canonical…}"` is not escaped. The CSP blocks script execution, but a `<meta refresh>` redirect is possible. Fix: `esc()` the value, and restrict route segments to `[a-z0-9-]`.
- **Medium — Page context goes in as a second `system` message, and the client can forge `assistant` history turns** (`handler.ts:96`). Move the context into the user turn inside delimiters, and don't trust history sent by the client.
- **Medium — The CORS preview regex accepts *anyone's* `nunya-togo-*.vercel.app` project** (`handler.ts:20`). Pin it to your team slug, and remove localhost in production.
- **Medium — Security headers only in a meta tag.** There is no `frame-ancestors` or X-Frame-Options, so clickjacking is possible, and no Permissions-Policy. Add them in `vercel.json`.
- **Low — Test pages are public** (`/test-onboarding.html` returns 200 and shares the app's localStorage). The article sanitizer uses a deny-list; switch to an allow-list.
- ✅ **Good:** no secrets in tracked files or git history; `.env` is ignored; only the publishable key ships to the browser; AI output is escaped; the service-role key is used server-side only.

### 3.2 AI assistant (Nunya Aide)
- **High — No moderation, no report button, no evaluation set.** Safety relies on the system prompt alone. Google Play also requires in-app reporting of AI content.
- **High — Groq capacity mismatch.** The published limits for gpt-oss-120b and gpt-oss-20b are 30 requests/min, 1K requests/day, 8K tokens/min and 200K tokens/day, per model and per organization. A request is about 1.5–6K tokens, so 300/day is not deliverable on the free tier, and a classroom gets 429 errors. On the paid Developer tier it costs about **$0.6 per 1,000 questions, roughly $5/month** at 300/day.
- **Medium — Robustness:**
  - `r.json()` outside try/catch leaks the reserved quota and returns a 500 without CORS headers (`handler.ts:143-146,185,191`);
  - one 25-second budget is shared by both models, so the fallback never runs after a hang;
  - the client fetch has no timeout or cancel;
  - every 401 silently creates a new anonymous user (`aide-panel.js:68-81`);
  - the function reads the legacy key env vars and there is no `supabase/config.toml` recording `verify_jwt=false`.
- **Medium — Fallback is cross-model, not cross-provider.** One base URL and one key means a Groq outage takes everything down. Recommended chain: Groq 120b → Groq 20b → Mistral Small (EU, French, has a moderation model) → Cloudflare Workers AI (10K free "neurons"/day).
- **Medium — Anonymous users are never cleaned up, and the AI session survives "delete my data" and profile switches.** On a shared phone, the next student inherits the previous one's session.
- **Low — Old copy** still says "the AI assistant is planned for a later version" (`dist/app.js:68,74`). `lib/ai/provider.ts` is dead code, and `.env.example` lists the wrong secret names.
- **Provider legality check:**
  - **Gemini API is excluded.** Its terms forbid clients likely to be used by under-18s.
  - **OpenRouter free models: avoid.** The limit is 50 requests/day, and some underlying providers may train on prompts.
  - **Groq is workable.** Its Services Agreement allows customer apps likely to be used by minors, with legal compliance being the customer's responsibility, and it forbids training on your data. But its *privacy policy* says its own services are not directed at under-18s. **Get written confirmation from Groq** and turn on Zero Data Retention.
  - **Mistral** requires parental consent for minors.

### 3.3 Architecture & code quality
- **High — Budget gate broken** (see summary #2). Win back headroom rather than raising the limit:
  - move about 41 KB gzip of lesson data that is compiled into JS (`curriculum.js`, `expansion-data.js`, `openlearn-courses.js`) out to JSON;
  - use esbuild `splitting:true, format:'esm'`;
  - lazy-load the library, assessment, resource-studio and Découverte modules.
- **Medium — Fragile structure.**
  - 23 hand-written, near-minified files live inside the **output** folder `dist/` and are concatenated into one scope: 497 top-level bindings, with `render` re-wrapped 10 times across 7 files, three routers and three placement-test implementations.
  - The build rewrites `dist/index.html` with a chain of `replaceAll('5.x','5.y')`, and versions are bumped by hand in `sw.js`.
  - Fix gradually: move sources to `src/` as ES modules with one router and one store, use content-hashed file names, and generate the SW manifest. A framework rewrite is not needed.
- **Medium — Weak static analysis.** `tsc` checks exactly one file (`lib/ai/provider.ts`), which is unused. ESLint enforces 6 rules. The Edge Function is not type-checked in CI.
- **Low:**
  - the production bundle runs in sloppy mode, because the CommonJS shim removes `'use strict'`;
  - `assessment-ui.js` writes `nunya-state` behind the store's back;
  - tests extract functions by slicing source text;
  - 14 empty `catch` blocks, and no global error handler.

### 3.4 PWA, performance & operations
- **High — The SW stores every navigation as `./index.html`** (`dist/sw.js:5`). Opening `guide-public.html` online, then the app offline, shows the guide page instead of the app.
- **High — Saved-course caches are never refreshed.** These are `nunya-curriculum-v1`, `nunya-academy-v1`, `nunya-library-v1`, `nunya-decouverte-v1` and `nunya-python-v1`. `caches.match` searches all caches, so learners who saved a course keep old content, UI strings and editor code forever, while the content is still draft and changing.
- **High — Network-first navigation with no timeout.** On weak 2G/3G links the installed app hangs for tens of seconds. Serve from cache, or race the network against a 2–3 s timeout.
- **High — No `navigator.storage.persist()`, and no limit on the runtime cache.** Low-storage Android phones can evict the whole origin, including all progress.
- **Medium:**
  - JS/CSS are precached twice (`f` and `f?v=5.4.0`): 688 KB fetched against 425 KB of unique files, about 38% wasted mobile data;
  - Pyodide (about 6 MB) is re-downloaded after every release unless the learner saved it;
  - the 3.7 MB library index is parsed on the main thread.
- **Medium — No error reporting, analytics or real-user data.** You cannot know whether installs or Python runs fail on real phones.
- **Medium — Repo weight.** 18.7k generated files are committed (`dist/` is 143 MB; the git pack is 40 MB after 5 commits), and import-only indexes such as `link_check_report.json` and `mdn-index.json` are publicly served. CI never checks that the committed `dist/` matches the build (no `git diff --exit-code`), and Python and Node versions are not pinned.
- **Hosting limits.**
  - **Vercel Hobby** is "non-commercial personal use only". An association, sponsor or school deal means Pro, or Cloudflare Pages, which allows 20k files per site; you are at 18.7k.
  - **The free Supabase plan** pauses after about a week of inactivity (school holidays) and has no usable backups.
- **Low:**
  - no update prompt;
  - manifest `theme_color` (#9a6544) differs from the HTML meta (#22684c);
  - `any maskable` icons are combined;
  - `noindex` makes the site invisible on Google: deliberate (`SOURCES_AND_LICENSES.md:36`), but it blocks discovery;
  - `guide-public.html` links to an old `nunya-togo-apprendre.shayrane45.chatgpt.site` address.

### 3.5 Content & pedagogy
- **High — No human review of anything served to minors.** All 42 legacy courses, 22 Python lessons and 20 Découverte lessons have `reviewer: null`. `CHANGELOG.md` says Découverte M1 was "validé par l'équipe", but no named reviewer is recorded, which contradicts `docs/CONTRIBUTING.md`.
- **High — Grading is easy to game.**
  - 36 of 88 Python exercises (all of M1 and M2-01 to M2-04) have no hidden tests or inputs, so printing the expected text passes.
  - In 20 exercises, hint 3 *is* the full solution.
  - Fix: add mutation tests in `test-curriculum-code.py`, AST/`required_syntax` checks, and make hint 3 a skeleton.
- **Medium — Review loop.** No spaced repetition: `state.curriculum.errors` is written and never read. Add Leitner-style boxes reviewed at 1, 3, 7 and 21 days, plus 2–3 retrieval questions at the start of each lesson.
- **Medium — Guessable quizzes.**
  - Python quiz options are unshuffled: answer positions are {0:11, 1:24, 2:26, 3:5} across 66 questions.
  - The correct answer is the longest option in 35 of 66.
  - In the placement test, 17 of 24 answers are "b", so always tapping the 2nd option scores 100% in web/digital.
- **Medium — Breadth vs depth.**
  - The README advertises "42 cours guidés … raisonnement pas à pas", but those are 37-word micro-lessons with one 3-option question each.
  - Freeze breadth, relabel them "fiches/aperçus", and invest in M5 (lists), M6 (functions) and a capstone project.
- **Medium — Language and grading details:**
  - instructions leave the exact expected text ambiguous (final full stop, French space before ":", straight vs typographic apostrophes);
  - M1 hints and outcomes are boilerplate;
  - there is no audio or images in the new courses (the old TTS button was not ported);
  - Python prose is abstract for second-language readers.
- **Medium — Local relevance:**
  - the security module deliberately leaves out **mobile-money fraud** (`docs/DECISIONS.md:57`), the main local scam aimed at teens;
  - alignment with the Togolese programme and its APC approach (competency-based teaching built on "situations-problèmes") is unverified (`data/togo_curriculum.json: "verified": false`).
- **Low:**
  - FCFA amounts shown with 2 decimals, and an invented currency "TST" (use the fixed EUR/FCFA parity of 655.957);
  - a sample passphrase that learners may copy;
  - 95 legal disclaimers inside lesson prose;
  - the schema id pattern `py-m[1-4]` will reject M5 and later lessons.
- ✅ **Good:**
  - correct French that respects learners;
  - accurate Python facts;
  - strong local anchoring;
  - Découverte is well calibrated (150–200 words per lesson);
  - an excellent single-source authoring pipeline;
  - reviewer packs (`docs/RELECTURE_NIVEAU0_*.md`) are ready to hand to teachers.

### 3.6 Onboarding, assessment & local data
- **High — The mandatory 10-question gate blocks everything.** Learners cannot reach the library, exam papers, backup import or shared lesson links until they finish it, and the original link is lost (`onboarding-flow.js:270-277`). For the Python domain the result does not change where the learner starts (always `py-m1-01`). The bank has only 24 items, so almost everyone sees the same 10. **Recommended:** make it skippable, preserve deep links, and add "J'ai déjà une sauvegarde" (I already have a backup) on the welcome screen.
- **High — Backup import drops `curriculum`, `discovery`, `onboarding`, `aide` and `events`.** The IndexedDB "backup" is write-only and never read back. Learners moving to a new phone lose the flagship course. Fix: a `nunya-backup-v2` format with migrations and a round-trip test.
- **Medium:**
  - every editor keystroke serializes the whole state to localStorage and six IndexedDB stores (no debounce);
  - shared-device profiles keep full copies in one localStorage key, with no quota handling;
  - "Culture numérique" routes to the cybersecurity path, and **Découverte (level 0) is never recommended**;
  - a score of exactly 70 is labelled "Bases solides" but starts at the bases stage.
- **Medium — The age gate** is a self-declaration that can be reversed instantly and that reveals the cutoff. It also conflicts with shipping 64 CEPD (primary-school) papers while blocking under-13s.
- **Medium — The sync schema is not ready for offline merging.** It has no tombstones, no server-side `updated_at` trigger, no schema version and no consent fields.

### 3.7 Testing & tooling
- `npm test` (88/88), lint and typecheck pass. `check:content` **fails** on the working tree.
- All 9 browser scripts hard-code `/Applications/Google Chrome.app/...`, so **none run on your Windows PC** or in CI. Use Playwright's own Chromium and add one e2e smoke job to CI.
- TEST_RESULTS claims "110" and "208" browser checks and SQL quota tests, but no script in the repo reproduces them.
- Coverage: about 8 of 31 modules are tested. The age gate, import/export, onboarding gate, SW and AI markdown sanitizer have no tests.
- There is no Dependabot, CODEOWNERS or SECURITY.md. `npm audit` reports 8 moderate issues, all dev-only.

### 3.8 Docs & legal
- **High — Missing legal pages:** no LICENSE, no *mentions légales* (publisher identity and contact), no terms of use, and no current privacy policy.
- **Medium — Licence labels and restrictions:**
  - OpenLearn adaptations are labelled "CC BY-NC", but OpenLearn's standard licence is CC BY-NC-SA 4.0. Check each source page.
  - The NC (non-commercial) clauses on Khan and OpenLearn material rule out any future paid offer that includes it. Write that down in DECISIONS.md.
- **Medium — Exam papers.** No permission from the Ministry is recorded for the 492 exam documents. They are only framed or linked, which is low risk, but get a letter before an institutional launch and **never cache them offline without permission**.
- **Medium — Docs contradict each other and production.**
  - README headlines 5.4.0 while production serves `nunya-v5.2.0`.
  - README says "no infrastructure / no AI".
  - DECISIONS says "migrations 001–003" while MIGRATION_PLAN says 001–006.
  - `package.json` is 0.3.0.
  - `docs/CHANGELOG.md` and `SOURCES.md` are stale duplicates.
- **Low:** the CodeMirror and KaTeX MIT licence notices are not shipped. Generate `THIRD_PARTY_LICENSES.txt` at build time.

#### Togolese law (Loi n° 2019-014, verified from the official text)
- **Art. 6:** processing of personal data must be **declared to the IPDCP**, which issues a receipt (*récépissé*) within one month.
- **Art. 8:** prior *authorisation* is needed only for special categories: health, biometrics, national ID numbers, file interconnection, criminal data and public-interest statistics. Nunya's current processing is probably declaration only. A lawyer should confirm this.
- **Art. 28:** **before any transfer to a third country** (Groq in the US, Supabase in France), the controller must **inform the IPDCP**, which gives a reasoned opinion. **Art. 30:** the IPDCP authorises transfers to countries without adequate protection when sufficient safeguards are offered.
- **Art. 4:** consent can be given by the data subject **or their legal representative**. For 13–17-year-olds, plan for parental information and consent.
- **Penalties:** administrative fines up to 100 M FCFA (art. 71), and criminal penalties of 100,000–25 M FCFA plus prison (arts. 79–93).
